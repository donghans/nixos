# 전력·입력 조사 근거 장부 (2026-10-21 기준)

`posture.md` 의 조사 기록에서 **어떤 주장이 어떤 근거 수준인지**를 한 곳에 모은 표. 규칙(2026-10-21 강화): 한 번의 관찰이나 상관은 "추정", 번갈아(ABAB) **3쌍 이상**에서 모든 쌍이 같은 부호이고 임계(전력 0.3 W) 이상이면 "측정". **2쌍 이하이거나 1회 비교는 "측정(약)"**(같은 방향이나 우연과 구분되지 않음 — 지표끼리 어긋나면 "유보"). 전력 판정은 psys·패키지·순간 V×I·누적 계량을 함께 보고(`observectl ab`), 5분 미만 구간의 순간 V×I·누적 계량은 신뢰 낮음으로 본다. 수준을 올리려면 마지막 열의 시험이 필요하다. 이후 새 결과는 이 표를 먼저 고친다. (`observectl ab` 가 판정을 자동으로 낸다 — 사용법은 observectl.md)


> **목적과 측정 조건 (2026-10-20 정정)**: 목적은 **Wayland(Hyprland) 세션을 쓰는 동안의 배터리 최적화**다. Claude 를 VT2(kmscon)에서 돌리는 것은 Wayland 세션 위에서 돌릴 때 생기는 변수를 줄이기 위한 **측정 위생**이며 원격 제어(RC) 용도가 아니다.
> 지금까지의 시험 대부분은 **덮개 닫힘 + VT2 활성**(패널 꺼짐, Hyprland 는 뒤에서 대기)이라는 **대리(proxy) 조건**에서 했다. 실제 사용(덮개 열림, 패널 켜짐, Wayland 활성)과 다르므로 아래 결과가 실제 사용에서도 유효한지는 **#37 에서 따로 확인**해야 한다. 내 Claude 세션의 부하(#34)는 사용자가 줄일 소비가 아니라 **측정에 섞이는 교란 요인**이다.

## 용어·단위 정정표 (2026-10-21) — 옛 수치를 읽기 전에

이 문서와 `posture.md` 의 **"깨어남/s", "CPU %", "low/high"** 는 시기에 따라 **서로 다른 도구·정의**로 센 값이라 숫자끼리 비교하면 안 된다. 해당 수치 옆에 `〔구표기 Ln〕` 를 붙였다(값은 그대로 두고 뜻만 밝힘).

| **L5** | `observectl bpf wake` (eBPF) | `sched_waking` 시스템 전체 (waker → wakee comm 쌍) | L5 끼리(L4 `--waking` 과 같은 종류) |

**새 이름(표본 형식 v2→v3, 2026-10-21):** L2 CPU → `cpu_core_pct`, **L9 → v3 에서 `ctxsw_vol_s`(모든 스레드 합)로 바뀌고 옛 표본의 값은 `ctxsw_vol_leader_s`(메인 스레드만, 합산·비교 금지)로 읽힘**, L3 → `observectl window` 의 `상위전환/s`(v3 의 `ctxsw_vol_s` 상위 프로세스 합; 옛 표본은 제외)·시스템 전체는 `irq.ctxt_s`, L6 → `cpu_all_pct`, 순간 V×I → `batt_vi_w`. 상세는 `observe.md` 의 "필드 이름과 단위".

같은 말이라도 규모가 다르다는 감각을 위해: 한 시점(2026-10-21, 덮개 닫힘 한가함)에서 eBPF `sched_waking` 은 시스템 전체 약 1,660/s, 수집기 상위 프로세스 합(L3)은 중앙값 약 115/s, 시스템 전체 문맥 전환은 약 2,500/s 였다.
