## 결론

첫째 프로필의 주기 활동은 번호 0 확장(비밀번호 관리자)의 서비스 워커다 — 60초마다 켜져 약 30초 돌고 꺼지며, 그때마다 앱 전체 CPU 가 5초 표본에서 0.34 s/s 로 튄다(약 1.7 CPU초/회, 평균 약 0.03 s/s).

## 상세

**첫째 프로필의 주기 활동은 번호 0 확장(비밀번호 관리자)의 서비스 워커다 — 60초마다 켜져 약 30초 돌고 꺼지며, 그때마다 앱 전체 CPU 가 5초 표본에서 0.34 s/s 로 튄다(약 1.7 CPU초/회, 평균 약 0.03 s/s).** 덮개 열림·AC·입력 장치 잠금, 노트북 시계 13:41~14:11, 서비스 워커 상태 이벤트(ServiceWorker 도메인)와 5초 CPU 를 같은 시계로 기록(`viv_sw.py`, 확장은 ID 앞 6자만).
이벤트 간격이 정확히 60초(1→32→61→92→124→154→184→214→244→274초)이고 CPU 튐이 같은 시각(5·65·125·185·246초)에 있다.
확장 코드에도 `alarms.create(…periodInMinutes:1…)` 이 있다.
다른 확장 서비스 워커는 이 구간에 주기 활동이 없다(하나는 상시 running).
**정정(#129·#132):** 번호 0 확장을 `chrome.management.setEnabled(false)` 로 껐다고 응답받은 뒤에도 같은 서비스 워커가 60초마다 계속 켜졌다(끈 뒤 300초 관찰에서 running 5회, 기준선 5회, 총 앱 CPU 같은 튐) — **프로그램으로 「끄기」는 그 워커를 멈추지 못했다**, 그러므로 #129 의 「확장은 원인이 아니다」 결론은 무효이고 #132 의 「Vivaldi 자체 확장일 가능성」 추정도 틀렸다.
이유는 미확인(끄기가 적용되지 않은 것으로 보임).
제거(`management.uninstall`)는 사용자 제스처 필요로 원격에서 실패 — 사용자가 `vivaldi://extensions` 에서 직접 제거해야 한다.
둘째 프로필에는 번호 0 확장이 없다(#131 의 0.01 s/s 와 일치).
근거: `_lab/netoff/sw-base.jsonl`·`sw-off0.jsonl`·`sw1.jsonl`
