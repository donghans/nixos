## 상세

**실제 프로필의 Vivaldi — 깜빡이는 텍스트 커서가 PSR 을 깬다(커서 깜빡임을 끄면 사라짐) — 덮개 열림·AC 모드(`tlp bat`)·밝기 100%·충전 안 함, 노트북 시계 09:27~11:12, 사용자의 두 프로필(개인·회사, 이름은 적지 않음)**: ① 빈 화면(3구간) psys 1.80~1.85 W·깨움 153~157/s·PC10 0.82~0.83·PSR 유지 100%. ② Vivaldi 를 켜 6분 뒤(구간 60초×3): 두 프로필 모두 **PSR 유지 약 0.71(IDLE 약 0.26)**, 패키지 C-state PC10 0.47~0.58, psys 3.1~4.4 W(빈 화면 +1.3~2.6 W), 앱 cgroup CPU 0.025~0.086 CPU초/s, 갱신 1.6~1.9/s(`perf stat intel_plane_update_arm`).
한 프로필은 입력창이 포커스된 웹 페이지, 다른 하나는 시작 페이지(주소창 포커스).
③ **원인 확인**: 입력창 영역을 0.12초 간격 10장 캡처하면 두 이미지가 교대로 나타남(약 0.5초 주기 = 커서 깜빡임).
시험 유닛에만 `XDG_CONFIG_DIRS` 로 `gtk-cursor-blink=false` 를 주고 띄우면 갱신이 20초에 34→0 회.
④ **ABAB(깜빡임 켬 A·끔 B, 각 2회, 안정화 240초+구간 60초×2)**: PSR 유지 켬 0.70·0.71·0.71·0.71 → 끔 0.99·0.995·0.995·0.996, 앱 CPU 켬 0.027~0.029 → 끔 0.0096~0.0107(−62%), 둘째 구간 psys 켬 3.50/4.94 W → 끔 2.58/2.62 W(쌍 차 +0.91·+2.32, 2/2 양수, 평균 약 −1.6 W), 깨움/s 둘째 구간 켬 341/527 → 끔 230/241, PC10 켬 0.48 → 끔 0.72. **한계**: 첫 구간(안정화 직후)은 켬·끔 모두 8 W 근처로 튀는 경우가 3/4 있어(깨움 900/s 이상, 원인 미확인 — 시작 후 5분경의 페이지 작업으로 추정) 판정에서 뺐고 둘째 구간만 썼음; 쌍이 2개뿐이고 켬 쪽 값이 3.50 대 4.94 로 크게 흔들려 와트 크기(−0.9~−2.3 W)는 정밀하지 않음 — 방향(PSR·CPU·C-state 가 일관됨)은 확실; 열린 페이지에 입력창이 없는 상태(커서가 없을 때)는 미측정; 다른 창·앱은 같은 설정 하나로 바뀌는지(Zed·kitty 는 자체 깜빡임 설정) 미확인.
