# 장부 #136 — 일하는 Claude TUI 에서 kitty 렌더 옵션(repaint_delay 10→50 ms, sync_to_monitor 끔)은 화면 갱신·PSR 을 줄이지 못한다…

> 장부 #136 행. 원본 `power-evidence.md` 표의 한 줄을 열 단위로 나눈 것이다(내용 변경 없음, 문장 단위로 줄만 바꿈). 새 행은 이 모양으로 쓴다.

## 결론

일하는 Claude TUI 에서 kitty 렌더 옵션(`repaint_delay` 10→50 ms, `sync_to_monitor` 끔)은 화면 갱신·PSR 을 줄이지 못한다 — 기본값이 가장 낫거나 같다.

## 상세

**일하는 Claude TUI 에서 kitty 렌더 옵션(`repaint_delay` 10→50 ms, `sync_to_monitor` 끔)은 화면 갱신·PSR 을 줄이지 못한다 — 기본값이 가장 낫거나 같다.** 덮개 열림·AC 모드(`tlp bat`)·밝기 100%(96000)·입력 장치 잠금, 노트북 시계 17:00~17:25, 일하는 TUI(Claude Haiku·모션 줄임·긴 도구 실행 하나) 상태에서 조건 3개를 A B C C B A A B C 순서로 3번씩(A=기본, B=`repaint_delay=50`, C=`sync_to_monitor=no`), 조건마다 안정화 40초+측정 90초, 9조건 모두 유효(실패 0·끝 상태 모두 work).
화면 갱신(`intel_plane_update_arm`) 기본 3.07/s·B 3.10/s·C 3.10/s, PSR 잔류 기본·B·C 모두 약 60%(SRDENT+SRDONACK+SRDOFFACK 기준 60.2/59.6/59.6%), 깨움 기본 529/s·B 542/s·C 533/s — 모두 3회 흩어짐(±0.04 갱신/s) 안에서 같다.
psys 는 기본 5.45 W(±0.03)·B 5.66 W(±0.04)·C 5.52 W(±0.07)로 **B 가 3번 모두 기본보다 높았다(+0.16~+0.30 W)** — 방향은 일관되나 3번뿐이고 갱신 수는 같아 원인을 모르므로 **추정**으로만 두고 채택하지 않는다.
해석: 갱신 횟수는 도구가 그리는 서로 독립인 1 Hz 카운터 두 개(#102)가 정하고 kitty 옵션은 이를 합치거나 없애지 못한다(구조 추정).
한계: **창 크기는 시험하지 않았다**(Hyprland 타일링이라 별도 부유 창 조작이 필요하고, PSR1 은 전체 프레임 방식이라 크기의 영향은 작을 걸로 추정), 한 일하는 상태·한 번의 날.
