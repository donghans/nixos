# 장부 #143 — 덮개 닫힘·AC 의 한가한 노트북에서 hrtimer_wakeup(약 76/s)의 주인은 tailscaled·containerd·blueman 트레이 셋이 75% 를 차지한다…

## 결론

덮개 닫힘·AC 의 한가한 노트북에서 `hrtimer_wakeup`(잠든 프로세스를 타이머로 깨우는 커널 함수, 약 76/s)의 주인은 tailscaled(29/s)·containerd(17/s)·blueman 트레이(10/s) 셋이 75% 를 차지한다 — 전력 영향은 미측정.

## 상세

**덮개 닫힘·AC 의 한가한 노트북에서 `hrtimer_wakeup`(약 76/s)의 주인은 tailscaled(29.3/s, 39%)·containerd(17.3/s, 23%)·blueman 트레이(10.0/s, 13%) 셋이 75% 를 차지한다 — 전력 영향은 미측정.**
덮개 닫힘·AC(`tlp bat`, 덮개 닫힘 정책), 노트북 시계 15:17:30~15:27:35(600초, 덮개를 닫은 90초 뒤 시작), 측정 중 이 호스트→노트북 ssh 없음, `perf record -a -e timer:hrtimer_start -e sched:sched_wakeup`(tmpfs 기록, `_lab/netoff/hrt_trace.sh`).
`hrtimer_start` 전체는 586/s: 유휴 틱 `tick_nohz_handler` 452/s(그중 swapper 416/s), `hrtimer_wakeup` 75.7/s, 데드라인 스케줄러 `dl_task_timer` 53.5/s, `timerfd_tmrproc` 4.7/s.
`hrtimer_wakeup` 을 시작한 프로세스: tailscaled 29.3/s, containerd 17.3/s, blueman 트레이 10.0/s, incusd 4.1/s, python3.13 2.2/s, 그 밖 각 1.5/s 이하(`perf` 자신 1.0/s).
깨워진 쪽(`sched_wakeup` 152/s): tailscaled 34.5/s, containerd 23.3/s, blueman 트레이 10.0/s, rcu_preempt 6.2/s, nsncd 4.9/s, incusd 4.8/s — 위 셋이 같은 순서로 나온다.
덮개 열림에서 ssh 가 있던 15초 맛보기(15:13)는 tailscaled 59/s 로 이 값의 두 배였다 — 측정 중 ssh 가 tailscaled 의 타이머를 늘린다는 장부 #108 과 맞는다(맛보기는 시험이 아니라 도구 확인이었다).
해석: 이 셋이 왜 도는지는 확인하지 않았다(tailscaled 는 연결 유지, blueman 트레이는 블루투스 상태 확인, containerd 는 도커·incus 컨테이너 런타임으로 추정). 깨움 1회의 에너지는 작아(R3, 추정 mW 규모) 이 셋을 끄면 얼마나 줄지는 상태 지표(깨움/s·PC10)를 먼저 본 뒤 필요할 때만 와트 ABAB 로 가린다.
한계: 한 번의 600초·한 날, 사용자 앱이 하나도 없는 상태(실사용 때와 다를 수 있다), `perf` 자신이 약 1/s 를 더한다.
