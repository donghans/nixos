> 장부 #60 행. 원본 `power-evidence.md` 표의 한 줄을 열 단위로 나눈 것이다(내용 변경 없음, 문장 단위로 줄만 바꿈). 새 행은 이 모양으로 쓴다.

## 결론

프로세스별 자발적 전환을 `/proc/<pid>/status` 로 읽으면 메인 스레드만 보인다 — 수집기(v1·v2 표본)·`boot_settle.py`·Netdata `app.*_cpu_context_switches` 모두 멀티스레드 프로세스를 크게 과소 집계

## 상세

**프로세스별 자발적 전환을 `/proc/<pid>/status` 로 읽으면 메인 스레드만 보인다 — 수집기(v1·v2 표본)·`boot_settle.py`·Netdata `app.*_cpu_context_switches` 모두 멀티스레드 프로세스를 크게 과소 집계**(전체 합 27%만 보임).
그래서 v1·v2 의 "상위 프로세스 전환" 순위·합계에 기댄 결론은 근거가 약하다: #39(상위 프로세스 활동이 low/high 에서 비슷), #40, posture.md 의 프로세스 깨어남 표

## 수준

**측정(10초 1회, 전체 413개 프로세스·1,341개 스레드 직접 합산 대조 — 값이 크게 달라 재현성 걱정은 작음)**

## 근거(조건)

같은 10초에 프로세스별로 (a) `/proc/<pid>/status` (b) `/proc/<pid>/task/*/status` 합을 비교: netdata(148 스레드) 363.5 대 0.0, vivaldi-bin(19) 60.0 대 0.3, electron(26) 59.8 대 0.3, .claude-wrapped(29) 399.6 대 100.7, 전체 1,744 대 474/s. Netdata `app.electron-39_8_10_cpu_context_switches` 는 5.8/s 인데 `/proc` 합은 같은 20초에 92/s. 반면 CPU(`/proc/<pid>/stat`)는 프로세스 전체 합이라 정확: Netdata `app.*_cpu_utilization`(제목 "100% = 1 core") 2.75 대 수집기 2.96(electron). **커버리지**: v4(`apps`)부터 전체 프로세스를 앱 단위로 합쳐 저장(상위 16행 한계 해소). **수정**: 수집기를 스레드까지 읽도록 고쳤다(스레드 1개 프로세스 제외, 30초 간격 +0.17% CPU), 표본 형식 v3, 옛 값은 `ctxsw_vol_leader_s` 로 읽어 합산·순위에서 제외
