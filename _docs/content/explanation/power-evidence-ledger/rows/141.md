# 장부 #141 — 일하는 Claude TUI 의 창 크기(전체 화면 2560×1576 vs 1/4 크기 1280×780)는 화면 갱신·PSR 을 바꾸지 못한다…

## 결론

일하는 Claude TUI 의 창 크기(전체 화면 2560×1576 vs 1/4 크기 1280×780)는 화면 갱신·PSR 을 바꾸지 못한다 — 크기를 줄여도 얻을 것이 없어 조치하지 않는다.

## 상세

**일하는 Claude TUI 의 창 크기(전체 화면 2560×1576 vs 1/4 크기 1280×780)는 화면 갱신·PSR 을 바꾸지 못한다 — 크기를 줄여도 얻을 것이 없어 조치하지 않는다.**
덮개 열림·AC 모드(`tlp bat`)·밝기 100%(96000), 노트북 시계 14:47~15:06, 일하는 TUI(Claude Haiku·모션 줄임·긴 도구 실행 하나) 상태에서 조건 2개를 F Q Q F F Q Q F 순서로 4번씩(F=전체 화면, Q=1/4 크기), 조건마다 안정화 40초+측정 90초, 8조건 모두 유효(실패 0·끝 상태 모두 work).
화면 갱신(`intel_plane_update_arm`) F 3.04/s·Q 3.06/s, PSR 잔류 F·Q 모두 약 57%, 깨움 F 529/s·Q 556/s — 조건 안 흩어짐(갱신 ±0.04/s, PSR ±3%p)과 같은 크기다.
psys 는 F 5.33 W(5.30~5.37)·Q 5.50 W(5.36~5.65)로 Q 가 평균 +0.17 W 높았고 pkg 는 F 1.39 W·Q 1.41 W(+0.02 W)였다 — 4번 중 3번이 F 의 최댓값(5.37)보다 높았으나 pkg 몫(b 약 2.8 기준 +0.06 W)으로는 설명이 안 되고 원인은 모른다. 방향도 「작은 창이 낮다」는 기대와 반대라 **추정**으로만 두고 채택하지 않는다.
먼저 한 시험(같은 날 14:22~14:41)은 모든 창이 기본 플로팅이고 기본 크기가 1280×1560 이라(`core.ux.nix` 의 `hl.window_rule({ match = { class = ".*" }, float = true })`) 「절반」 조건이 기본과 같은 크기였다 — 크기를 바꾸지 않은 널 비교가 됐다. 그 시험에서 같은 일하는 조건의 psys 가 5.29~9.11 W, PC10(패키지 깊은 잠 비율) 6~49% 로 크게 흔들렸다(같은 조건 4번). 이 틀의 일하는 TUI 소음이 바로 앞의 재시험(psys 5.30~5.65 W, PC10 모두 0%)과도 다르다는 뜻이라, 흔들림의 원인(백그라운드 작업·시험 직전 상태)은 모르고 이 틀의 일하는 TUI 와트 판정에는 널 시험이 먼저 필요하다.
한계: 한 날·한 일하는 상태·창 위치 고정(왼쪽 위), 한가한 TUI 는 PSR 잔류 99%·갱신 0.06/s 라 크기를 바꿔 보지 않았다(널 시험에서 같은 값).
근거: `_lab/netoff/ds-winsize-2.jsonl`(재시험, `disp_state.py` 의 `:full`·`:quarter` 조건), `_lab/netoff/ds-winsize-null-1.jsonl`(널 비교, 크기 1280×1560 동일)
