## 상세

**번호 0 확장(비밀번호 관리자) 제거 후 첫째 프로필 Vivaldi 의 주기 활동이 사라졌다 — 앱 CPU 0.046→0.002 s/s, 깨움 중앙 262→193/s, psys 중앙 2.63→2.32 W(약 −0.3 W, 추정).** 사용자가 `개인` 프로필에서 그 확장을 직접 제거(원격 제거는 제스처 요구로 불가, #133)한 뒤, 덮개 열림·AC·`tlp bat`·입력 장치 잠금, 노트북 시계 14:14~14:54. (1) 서비스 워커 이벤트 300초: 확장 워커 시작이 시작 때 1회뿐(제거 전 60초마다 5회), 5초 표본 중 앱 CPU>0.1 s/s 가 0/60(제거 전 5/60), 총 앱 CPU 평균 0.0097→0.0040 s/s. (2) 평소 띄움 안정화 240초+45초 창 4개 ×2 블록: 앱 CPU 0.001~0.003(첫 창 포함 전부), 깨움·psys 는 첫 창(6.0·6.4 W, 안정화 직후 튐)을 빼면 중앙 2.32 W(2.13~3.53, 평균 2.46), 이전 제거 전(#130, 같은 틀·첫 창 제외) 중앙 2.63 W(평균 2.64)와 `--disable-extensions`(중앙 2.12 W, 평균 2.86 W — 한 블록 오염)의 사이다.
한계: 제거 전후가 같은 날이나 따로 잰 비교(순서 교차 없음), 블록 2개, 창마다 흔들림 ±0.15 W 안팎이라 전력 차 약 0.3 W 는 방향만 확인되는 수준, pc10 은 전 조건 0(이 틀의 측정값 그대로).
서비스 워커 주기 활동 소멸과 앱 CPU 감소는 직접 확인.
남은 확장 3개는 이 구간에 주기 활동 없음.
