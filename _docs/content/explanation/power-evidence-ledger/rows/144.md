# 장부 #144 — 덮개 닫힘·AC 모드의 한가한 노트북에서 rootless docker 와 blueman 을 함께 끄면 psys 가 평균 0.24 W 줄었다(6/6)…

## 결론

덮개 닫힘·AC 모드의 한가한 노트북에서 rootless docker 와 blueman 자동 시작 유닛을 함께 끄면 psys 가 평균 0.24 W 줄었다(6쌍 모두 같은 방향) — 약 88% 가 CPU 패키지 몫이고, 이 중 docker 만의 몫은 작다(#145), 사용자가 블루투스 키보드를 쓰려고 blueman 은 켜 두기로 해 조치하지 않는다.

## 상세

**덮개 닫힘·AC 모드의 한가한 노트북에서 rootless docker 와 blueman 자동 시작 유닛을 함께 끄면 psys 가 평균 0.24 W 줄었다(6쌍 모두 같은 방향) — 약 88% 가 CPU 패키지 몫이다.**
덮개 닫힘·AC 모드(`tlp bat`)·손대지 않음·사용자 앱 없음(컨테이너는 전부 종료 상태, 데몬만 떠 있음), 노트북 시계 15:36~16:25, 구간 240초(안정화 90초)×12, 순서 A B B A A B B A A B B A(A=평소, B=`docker.service`·`app-blueman@autostart.service` 정지), 모든 구간 덮개·AC 유지(`_lab/netoff/usvc_abab.sh`, 정지는 유닛 응답이 아니라 `dockerd`·`containerd`·`.blueman-applet`·`.blueman-tray-w` 프로세스 소멸로 확인).
psys A−B 쌍별 +0.412 +0.204 +0.335 +0.211 +0.029 +0.261, 평균 +0.242 W(표준편차 0.131, 6/6), 이웃 B 평균으로 표류를 보정하면 +0.207 W.
pkg A−B 평균 +0.088 W(6/6). b=2.42(#142, 덮개 닫힘·배터리의 날짜 간 b)로 나누면 CPU 패키지 몫 +0.213 W, 패키지 밖(화면·Wi-Fi·SSD) 몫 +0.029 W.
절대 값: psys A 구간 0.89~1.15 W, B 구간 0.70~0.86 W — 한가한 덮개 닫힘의 전력이 작아 0.24 W 는 약 25% 이다. 앱을 쓰는 실사용에서의 비중은 이보다 훨씬 작다.
쌍 5 만 +0.029 W 로 작았다(B #5 시작 직후 표본이 높다는 안정화 경고) — 이 쌍을 빼면 평균 +0.285 W 로 결론이 같다. 첫 구간(A #1)이 가장 높다(1.14 W).
앞선 R4 SIGSTOP 시험(2026-10-23, 3라운드·60초)의 containerd −0.11 W·blueman 트레이 −0.08 W 보다 합이 큰데, 그때는 3라운드·60초였고 얼리는 것과 끄는 것이 달라 직접 비교하지 않는다.
한계: 두 유닛을 함께 껐으므로 각각의 몫은 이 시험으로 못 가른다(docker 단독은 #145). 한 날·AC 모드·사용자 앱 없는 상태.
조치: **하지 않는다** — 사용자가 블루투스 키보드를 상시 쓰기로 해(2026-10-28) blueman 을 끌 수 없다. 설정은 바꾸지 않았다.
