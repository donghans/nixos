## 상세

**독 환경이 패키지를 깊은 절전에 못 들게 하는 원인 좁히기(소프트웨어 쪽, 독 꽂음·덮개 닫힘·AC 자동 정책, 디스플레이 비활성)**: 독 꽂은 뒤(18:22) pc10 0%·pc8 0%·**PC2 약 76%**(독 없을 때 pc10 약 55~62%).
① XHCI 의 LTR(0.4 ms)을 `pmc_core/ltr_ignore` 로 무시해도 변화 없음(pc10 0%) → **XHCI LTR 은 원인이 아님**.
② 독 USB 장치 3개(LAN·Billboard·오디오)의 런타임 PM `on→auto`: pc10 0→2.4%, pc8 0→8%, PC2 76→63% — **부분 개선만**(Billboard·오디오는 suspended, LAN 은 auto 여도 active 유지).
시험 후 3개 모두 `on` 으로 원복, ltr_ignore 도 복구.
추가(독에서 USB-C DP-alt 디스플레이 케이블만 뽑은 뒤, 60초 MSR 구간): ③ 케이블 제거 후 PC2 76→56%·PC3 0→21%·pc10 0%(일부 개선뿐).
④ LAN(2-1.4) `authorized=0` → TBT xHCI(00:0d.0) 인터럽트 31→0/s 이지만 패키지 상태는 그대로(pc2 57·pc3 22) → LAN 은 깨움 원천이나 pc10 차단 주범은 아님.
⑤ **독 USB 경로 전체(허브 2-1·3-5) `authorized=0`: pc10 약 3.5%·pc2 약 73%** — USB 를 논리적으로 다 끊어도 독 없을 때(pc10 55%)로 안 돌아옴 → **원인은 USB 가 아니라 독의 전원/PD(UCSI)·Thunderbolt 컨트롤러·링크 쪽으로 좁혀짐**(단 각 시험은 60초 1~2회·구간 간 변동 있음).
모든 시험 뒤 원복 확인.
아직 못 가린 후보: Type-C(UCSI) 포트 PD/alt 모드 상태·Thunderbolt 컨트롤러(00:0d.0 active)·PCIe 링크
