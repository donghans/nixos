# LLM 에이전트 도구의 이식성 — 어디가 중립이고 어디가 Claude 전용인가

donghans 워크스테이션의 스킬·ctx·QA 도구는 지금 Claude Code 위주로 쓴다. 나중에 다른 LLM 에이전트(Gemini CLI·Codex 등)로 옮길 때 **치환할 것이 적도록**, 결합 지점을 분류하고 바꿀 때의 체크리스트를 남긴다(2026-10-23 감사).

## 1. 결론
- 본문(원칙·절차·DB·도구 스크립트)은 대부분 **에이전트 중립**이다. 스킬 본문은 에이전트 전용 도구를 괄호로 표시하고 기본 수단을 따로 둔다.
- 치환이 필요한 것은 **이름·경로**(스킬 폴더, 지침 파일, 프로젝트 지침 디렉터리)와 **독자 기능 5가지**(아래 §3)다.
- **독자 기능 중 대체 수단이 없어 설계를 바꿔야 하는 것은 「세션 간 메시지」와 「대화 적재 형식」 둘**이다. 앞의 것은 점유 알림을 파일 기반으로 이미 이중화했다(`occupy.py`).

## 2. 분류

### A. 에이전트 중립 (그대로 쓰임)
| 부분 | 근거 |
|---|---|
| `donghans-qa` 의 원칙 본문(§1~§7) | 측정 정직성·범위 렌즈·격리·보고 규약. 도구 이름 없음 |
| 프로젝트 지침 파일 규약(`.claude/donghans-instructions.md` 의 절 제목으로 용도 구분) | 파일은 마크다운, 읽는 쪽은 `context.py`. 디렉터리 이름 `.claude/` 만 에이전트 흔적 |
| `context.py` (점검·`--init`·worktree 처리) | git 과 파일만 사용 |
| `ws.py` · `snap.py` · `occupy.py` | VM 의 GNOME·PipeWire·파일, 호스트의 ssh 만 사용 |
| ctx 조회·치환·주입 래퍼·후보 탐지·`ctxui` | Postgres 표(role/kind)만 본다. 조회·치환·`secret run` 은 어떤 에이전트의 셸에서든 동작 |
| QA VM(`qa-desktop`)과 창 배치 규칙 | 에이전트와 무관한 인프라 |

### B. 이름·경로만 바꾸면 되는 결합
| 지점 | 지금 | 바꿀 때 |
|---|---|---|
| 전역 지침 파일 | `~/.claude/CLAUDE.md` (`mods/devel/apps/llm-cli.nix` 가 생성) | 에이전트별 파일명(`GEMINI.md`·`AGENTS.md` …). 같은 텍스트를 `home.file` 에 한 줄 더 선언(llm-cli.nix 에 Gemini 용 주석 스텁이 이미 있다) |
| 스킬 폴더·형식 | `~/.claude/skills/<이름>/SKILL.md` (frontmatter `name`·`description`) | 해당 에이전트의 스킬/확장 위치. 스킬을 자동으로 읽지 않는 에이전트는 전역 지침에 「먼저 이 파일을 읽어라」 포인터를 둔다 |
| 프로젝트 지침 위치 | 저장소의 `.claude/donghans-*.md` | 디렉터리 이름만 바꾸면 된다(`context.py` 의 `NAMES`·`roots`). 파일 내용은 그대로 |
| 에이전트 표식 환경변수 | `CLAUDECODE` · `GEMINI_CLI` · `DONGHANS_AGENT` (`llm_ctx.py` 의 `AGENT_ENV_MARKERS`) | 새 에이전트의 표식을 목록에 추가하거나 래퍼에서 `DONGHANS_AGENT=1`. **본체는 TTY 검사**라 표식이 없어도 에이전트 셸은 막힌다 |
| 모델 이름 지침 | 「정답이 명확한 읽기·치환 = haiku, 판단은 sonnet」 | 해당 에이전트의 모델 등급 이름으로 |
| `claude -p` | `donghans handoff draft` 가 작은 모델 호출에 사용 | 다른 CLI 의 비대화 호출로 |

### C. Claude 전용 독자 기능 (대체 설계가 필요)
| 기능 | 어디서 쓰나 | 대체/완화 |
|---|---|---|
| **세션 간 메시지**(`SendMessage`·`ListAgents`) | QA↔수정 세션 요청·회신, VM 점유 알림 | 점유 알림은 파일 기반 `occupy.py` 가 기본 수단(메시지는 가속 수단). 요청·회신은 인계 문서 + 사용자 중계로 대체 가능하나 자동 왕복은 불가 |
| **대화 적재 형식**(훅 JSON·`~/.claude/projects/**/*.jsonl`·OTel) | `llm-ctx` 적재·`secret scrub` | 에이전트별 어댑터가 필요(`mods/_tools/llm-ctx/agents/<이름>.py` — 대화 파일 위치·`parse_line`·환경 표식; `scrub` 대상 경로도 같은 어댑터에서 나온다. 인터페이스는 `agents/__init__.py` 머리말). 아직 어댑터 밖: 훅 입력 JSON·OTel·한도 기록(`llm_ctx.py`). DB 표·조회·치환은 그대로 |
| **스킬 자동 발견·`Skill` 도구** | 모든 스킬 | SKILL.md 본문은 그대로 쓰되 호출 경로가 다르다(위 B) |
| **한도·사용량 도구**(상태 표시줄·`donghans-limit-watch` 스킬·`Monitor`) | 세션 사용량 지침, 사용량 TUI | Claude 구독 한도 모델 전용 — 다른 에이전트는 별도 도구 필요 |
| **하위 에이전트·권한 분류기**(`Agent` 도구·`/permissions`·`AskUserQuestion`) | 전역 지침의 비용 규칙, ToT QA 문서의 분류기 절 | 지침 문구만 바꾸면 되는 부분과 기능 자체가 없는 부분이 섞여 있다 |

## 3. 이번 감사에서 고친 것(오해·결합)
- **worktree 에서 프로젝트 지침을 못 찾던 결함**: `context.py` 가 현재 작업 트리만 보고 「지침 없음, 새로 만들라」고 안내했다. 추적 제외 파일은 메인 체크아웃에만 있어서, ToT QA 처럼 `.claude/worktrees/qa-docs` 에서 일하는 세션이 틀린 안내를 받았다 → 메인 체크아웃에서도 찾도록 수정.
- **추적 제외 규약의 설명 부족**: 스킬에 why·한계·경계가 없었다 → `donghans-qa` §0-A 에 추가: `.git/info/exclude` 를 쓰는 이유(커밋되지 않아 다른 개발자에게 영향 없음), **이 머신에만 있음**(다른 머신·클론에는 없음), 프로젝트 사실은 여전히 추적 문서에(전역 원칙), 이미 추적 중인 파일엔 효과 없음, 제외가 안 돼 있으면 경고.
- **처음 보는 프로젝트의 시작점이 없던 문제**: `context.py --init` 이 지침 틀을 만들고 추적 제외를 설정한다(멱등, 덮어쓰기·커밋 없음).
- **세션 설정이 안 된 호스트에서의 막다른 길**: `donghans-qa-desktop` 에 「사전 점검」을 추가 — VM·키·접속·프로젝트 규칙·점유 확인, 어긋나면 임의로 고치지 않고 사용자에게.
- **Claude 전용 표현**: 스킬·코드의 「Claude 가 …」를 「에이전트가 …」+ 괄호의 도구명으로, 「사람만」 판정에서 `CLAUDECODE` 를 보조 표식으로 격하하고 TTY 를 본체로 명시(가상 터미널로 시험).

## 4. 다른 에이전트로 옮길 때 체크리스트
1. 전역 지침 파일을 새 에이전트의 파일명으로도 생성(`llm-cli.nix` 의 `home.file`) — 텍스트는 거의 그대로.
2. 스킬 위치·호출 방식 확인. 자동 호출이 없으면 전역 지침에 스킬 파일 경로를 직접 적는다.
3. `AGENT_ENV_MARKERS` 에 새 에이전트 표식 추가(또는 래퍼에서 `DONGHANS_AGENT=1`).
4. 대화 적재: 새 에이전트의 기록 형식 파서·훅(또는 타이머) 추가. 안 하면 ctx 에는 Claude 대화만 쌓인다(조회·치환은 영향 없음).
5. 세션 간 협업이 필요하면 `occupy.py`(점유) + 인계 문서(요청·회신)를 기준으로 삼는다.
6. 모델 이름·`claude -p`·한도 도구 문구를 해당 에이전트 것으로.
7. 프로젝트 지침 디렉터리명(`.claude/`)을 바꾸려면 `context.py` 의 `NAMES`·경로 한 곳과 각 프로젝트의 `.git/info/exclude` 를 갱신.
