# donghans-test-judgment — 시험을 만들기 전에 가른다

**이 스킬은 새 시험을 만들기 전의 판단이다. 기존 시험을 감사하거나 지우거나 고치라는 지시가 아니다**(기존 시험은 사용자가 직접 감사한다). 새 시험을 만들다 인접 시험이 깨져 있는 것을 보면 **보고만** 하고, 고치는 것은 사용자 허락 뒤에 한다.
용어: **장기 보호용(A)** = 저장소에 남겨 앞으로의 모든 변경 때 돌리는 시험. **단기 확인용(B)** = 이 수정이 먹혔는지 한 번 보는 임시 시험(저장소에 남기지 않음). **변이 검사** = 시험이 지키는 코드·핵심 단언을 일부러 깨 보고 시험이 **실패하는지** 확인하는 것(실패하지 않으면 그 시험은 아무것도 지키지 않는다).

## 절차
1. **지키는 것 한 문장**: 「이 시험은 ○○ 라는 결정·불변식이 깨지면 실패한다」. 한 문장으로 못 쓰면 시험을 만들지 말고(D) 무엇을 확인하고 싶은지부터 정한다.
2. **깨졌을 때 피해**(하나라도 해당하면 A 후보): ① **조용히 틀림** — 화면·로그에 티가 안 나는데 결과가 틀림(예: 비밀 치환이 `[protected]` 로 안 바뀜) ② **되돌릴 수 없음** ③ **보안·사람만 해야 하는 동작**(예: `--raw`·`procctl` 보호) ④ **데이터 손실·오염**(예: 적재 멱등성, 원본 보존). 모두 아니면 겉모양·문구·배치는 시험으로 잠그지 않는 것이 기본이다. 예외는 **LLM 이 읽는 문구가 계약**인 경우(예: 모델이 파싱하는 `[잘림: …]` 표지).
3. **판정**
   - **A 장기 보호**: 위 ①~④ 에 걸림 → 저장소 시험으로 만들고 `mods/_tools/run-tests.sh` 에 등록한다. **그 파일의 인터프리터 목록을 맞춰 넣는다** — `python3 -I` 목록·textual 이 든 `PY`·psycopg+textual 이 든 `CTXPY` 줄이 따로 있고, `CTXPY` 가 없으면 그 줄은 조용히 건너뛴다.
   - **B 단기 확인**: 지금 이 수정이 먹혔는지만 보면 됨 → 스크래치 폴더에서 한 번 돌리고 결과만 응답·커밋 메시지에 적는다. 저장소에 남기지 않는다. 환경을 바꿨으면 원래 값을 기록해 두고 끝나면 복원·재확인한다.
   - **C 다른 수단**: 평가·빌드(`nixup check`), 코드 안의 단언·타입, 문서 대조, **이미 예정된 시험 묶음의 관찰 항목**이 더 싸다. 배포가 되는지는 시험이 아니라 `nixup check` 의 몫이다.
   - **D 만들지 않음**: 지키는 것을 한 문장으로 못 쓰거나, 깨져도 피해가 없다.
4. **A 를 만들 때의 조건**: 날짜·시각을 고정하지 않는다(오늘 기준 상대 날짜 — 고정 날짜 시험은 시간이 지나 기간 밖이 되어 깨졌다). 외부 상태(현재 시각·네트워크·다른 시험 결과)에 기대지 않는다. **변이 검사를 1회** 하고 결과 한 줄(무엇을 깼더니 어느 시험이 실패했나)을 커밋 메시지에 남긴다. 문구 못 박기는 계약인 것만.
5. **시험 의존 가드(두 번째부터)**: 같은 의문에 **두 번째** 시험을 파기 전에 「이미 예정된 시험에 끼울 수 있나 / 안 확인해도 장기적으로 문제없나」를 먼저 한 줄로 적는다. **금지가 아니라 질문**이다 — 효과 확인이 필요하면 하되 한 묶음으로 하고, 횟수 한도(숫자)는 없다. 확인하려는 의문마다 시험을 새로 파는 반복을 경계하는 것이다.
6. **남기는 것**: 응답·계획서·커밋 메시지에 한 줄 — `시험 판정: A|B|C|D — <지키는 것 한 문장> — <이유 한 줄>`. 판단이 서지 않으면 **B 로 하고 이유에 「확신 없음」** 을 적는다(되돌릴 수 있는 쪽). 시험이 없는 변경에 이 줄을 억지로 붙이지는 않는다.

## 예 (이 저장소의 실제)
| 상황 | 판정 | 이유 |
|---|---|---|
| 비밀 값이 출력에서 `[protected]` 로 바뀌는 처리 | A | ① 조용히 틀림 + ③ 보안. 치환이 빠져도 화면에 티가 안 남 |
| 사용량 시험 데이터가 고정 날짜(2026-10)여서 시간이 지나 대시보드 기본 기간(30일) 밖이 되어 깨짐 | 이 시험은 A 의 **날짜 조건(4번)** 위반 | 새로 쓸 때는 `_ago(d)` 같은 상대 날짜. 기존 시험은 이 스킬이 고치지 않는다 |
| 이번 수정으로 오류 문구가 바뀌었는지 한 번 눈으로 확인 | B | 지금 한 번이면 충분, 저장소에 남길 이유 없음 |
| 새 모듈이 호스트에서 빌드·활성화되는가 | C | `nixup check` 가 직접 답한다 |
| 목록 화면의 열 배치·여백 | D | 깨져도 피해 없음(겉모양) |
