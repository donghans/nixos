# donghans-handoff — 세션 인수인계 작성 (범용)

**원칙: 다음 세션이 사용자에게 되묻지 않고 이어갈 수 있을 만큼의 확실한 정보만, 오해 없는 표현으로.** 사실(코드·git 으로 확인) / 추정 / 사용자 발언 / 에이전트 보고를 섞지 않는다.


## 호출 뒤에 붙은 추가 지시 (ARGUMENTS)
`/donghans-handoff <추가 지시>` 처럼 뒤에 글이 붙으면 **이번 인수인계의 작성 방침으로 최우선 반영**한다. 예: 「A 를 중점으로」「B 는 상세 문서까지」「성능 관점으로 정리」「QA 에게 넘길 것 위주로」. 규칙:
- 절차 시작 전에 추가 지시를 한 줄로 되풀이해 해석을 확인하고(모호하면 한 번에 모아 질문), 문서 상단에 `focus:` frontmatter 로 원문을 남긴다(다음 세션이 왜 이렇게 쓰였는지 알도록).
- 「상세히」「자세히」가 붙은 주제는 아래 **상세 문서**로 뺀다. 중점 주제는 본문 앞쪽·분량 배정을 늘린다.
- 추가 지시가 기본 절차(120줄, 구조)와 충돌하면 추가 지시가 이긴다. 단 사실/추정 구분, 커밋하지 않기, 등록은 지킨다.
- 같은 지시가 여러 번 나오거나 사용자가 「상시로」라고 하면 아래 「채택된 상시 추가 지시」 절에 반영할 것을 제안한다(스킬 원본: `~/nixos/mods/_data/claude-skills/donghans-handoff/SKILL.md` — 사용자 승인 후에만 고친다).

## 프로젝트별 지침 (선택, 보통 `.git/info/exclude` 로 추적 제외)
저장소 루트의 `.claude/donghans-instructions.md`(기본 절차에 **추가 적용**)와 `.claude/donghans-override.md`(기본 절차와 **충돌하면 이쪽이 우선**)가 있으면 따른다. **절차 시작 전에 `donghans instr show --section "handoff 할 때"` 로 읽는다**(먼저 공유 저장소와 맞춘 뒤 해당 절만 보인다 — 「생략된 절」 안내가 나오면 필요한 만큼 `donghans instr show`; 명령을 못 쓰면 `cat <저장소>/.claude/donghans-{instructions,override}.md`). 문서 형식·커밋 규약·갱신할 상태 파일 등 저장소 고유 규칙은 여기에 있다. resume 쪽도 같은 파일을 읽으므로 인수인계에 적을 때 그 전제를 두어도 된다.

> **공유 정본(2026-10-23)**: 이 두 파일의 정본은 공유 저장소(ctx DB)이고 로컬 파일은 읽기 전용 캐시다. 읽기는 `donghans instr show`(최신화 후 출력), 고치기는 `donghans instr edit|set`(DB 먼저). `claude` 래퍼의 SessionStart 훅도 세션 시작 때 맞춘다(없으면 만들고, DB 가 더 새로우면 갱신, `.git/info/exclude` 도 보정). 캐시를 우회해 직접 고친 앞섬·충돌은 알림만 하고 덮지 않는다(`donghans instr diff`). 본문에 비밀 값을 적지 말 것(올릴 때 등록표로 검사해 거부).

## 절차
1. **지금의 사실을 먼저 얻는다(기억으로 쓰지 않는다):** `git status --short`, `git log -1`, `git worktree list`, 미병합 브랜치(`git log --oneline HEAD..<br>`), 진행 중 백그라운드 작업. 
2. **상시 지시를 모은다:** 이 대화에서 사용자가 준 방침·금지·선호를 원문에 가깝게. **지시마다 「출처」(누가·언제·어느 세션/문서) 와 「확인」(사용자 원문 확인 / 문서에서 옮김 / 에이전트 해석)을 표로 붙인다.** 출처를 못 대면 상시 지시가 아니라 「추정」으로 내린다. 이어받은 인수인계에서 옮겨 적는 지시는 *원 출처를 유지*하고 「옮겨 적음」이라 표시한다(복사가 거듭되며 사용자 발언처럼 굳는 것을 막는다). 사용자 발언 추적이 필요하면 트랜스크립트(`~/.claude/projects/*/<세션ID>.jsonl`)를 `grep` 으로 좁혀 확인한다 — 컨텍스트 압축 요약 속 인용은 원문이 아니다. 직전 HANDOFF 문서의 상시 지시 중 아직 유효한 것은 유지. 사용자의 환경 규칙은 `~/.claude/CLAUDE.md` 가 이미 로드되므로 반복하지 않는다.
2.5. **초안 (세션이 크면 — 컨텍스트가 대략 절반 이상이거나 사용자가 요청):** 큰 컨텍스트를 이 세션이 다시 읽어 요약하면 사용량이 크게 오른다. 대신 `donghans handoff draft --session $CLAUDE_CODE_SESSION_ID [--focus "<추가 지시>"]` 를 실행한다 — DB(공유 저장소)의 사용자 발언·최근 응답만 작은 모델(기본 haiku)에 넘겨 `.claude/handoffs/DRAFT-<세션ID>.md` 를 만든다(입력 크기는 stderr 에 출력됨; `--dry-run` 으로 먼저 볼 수 있다). **초안은 검증 전 자료다:** 이 세션이 (1) 사실 칸을 git·파일로 직접 확인하고 (2) 상시 지시의 「확인」 칸을 원문과 대조하고 (3) 에이전트 해석이 사용자 결정으로 둔갑한 곳을 바로잡은 뒤 아래 3번 문서로 확정한다. 초안은 대화의 뉘앙스를 잃을 수 있으므로 *그대로 쓰지 않는다*. DB 에 못 붙으면(실패 메시지) 기존 방식으로 직접 쓴다.
3. **문서를 쓴다:** 기본 위치는 **저장소의 추적 제외 경로 `.claude/handoffs/HANDOFF-<세션ID>.md`** (`echo $CLAUDE_CODE_SESSION_ID` 전체 — **날짜가 아니라 세션 ID 로 이름을 짓는다**: 같은 저장소에서 여러 세션(수정·QA 등)이 동시에 인수인계해도 서로 덮어쓰지 않는다) (없으면 만들고 `.git/info/exclude` 에 `.claude/handoffs/` 가 있는지 확인해 없으면 추가). 이 스킬의 목적은 *이 머신에서 빠르게 컨텍스트를 복원*하는 것이지 이력 공개가 아니다. 프로젝트 지침 파일이 다른 위치를 지정할 때만 따른다. 같은 세션에서 다시 인수인계하면 그 파일을 갱신한다. 이어받은 이전 인수인계가 있으면 frontmatter `supersedes` 에 그 ID 를 적는다. **본문은 최대 약 120줄**(길어지는 것은 상세 문서로 뺀다 — 아래).
   - frontmatter: `version`, `updated`, `status`, `handoff_id: $CLAUDE_CODE_SESSION_ID`(`echo $CLAUDE_CODE_SESSION_ID`), `branch/HEAD(푸시 여부)`, `supersedes`
   - frontmatter 에 추가 지시가 있었으면 `focus: <원문>`.
   - 본문: 0 상시 지시 · 1 현재 상태(확인 방법/날짜) · 2 미병합·미완 작업(브랜치·SHA·검증 여부) · 3 다음 할 일(순서·예상 비용·위험) · 4 열린 결정(추천 답 포함) · 5 함정과 환경 팁 · 6 다른 세션/사람과의 연결 · 7 못 쟀거나 낡았을 수 있는 것
   - 채팅에서만 있던 결정·전언은 출처를 붙인다. 코드로 확인하지 않은 것은 「추정」.
   - **상세 문서 (필요한 만큼만):** 본문에 다 못 담는 정보(조사 결과·결정 근거·함정의 재현법·표/목록 원본·다른 세션 전언 전문 등)는 `.claude/handoffs/<세션ID>/NN-주제.md` 로 만들고, 본문에 **인덱스 표**로만 가리킨다:
     | 파일 | 한 줄 요약 | 언제 읽나 | 근거 대화 범위 |
     |---|---|---|---|
     | `<세션ID>/01-…md` | … | 다음 할 일 3번 착수 전 | `<시작uuid8>~<끝uuid8>` |
     「근거 대화 범위」는 그 내용의 근거가 된 대화 구간이다(`donghans ctx session <세션ID> --from <시작> --to <끝>` 로 그 구간만 조회). 범위를 적는 것은 *필요한 구간만 읽게 하려는 것*이지 요약 비용을 미루는 것이 아니다 — resume 이 범위 전체를 습관적으로 읽으면 의미가 없다.
     상세 문서는 그 주제 하나만, 자기완결적으로(본문을 안 읽어도 이해되게), 사실/추정 구분과 확인 날짜를 갖춘다. 표의 「언제 읽나」가 없으면 resume 쪽이 읽을 시점을 모른다. 추가 지시로 「상세히」가 온 주제는 반드시 여기로 뺀다. 상세 문서도 추적 제외 디렉터리 안에만 둔다.
4. **커밋·푸시하지 않는다**(추적 제외 문서이므로 커밋할 것이 없다). 저장소의 추적 파일(상태 문서 등)은 사용자가 요청하거나 프로젝트 지침이 명시할 때만 고친다.
5. **등록하고 안내한다:** `python3 ~/.claude/skills/donghans-handoff/scripts/register.py --doc <문서경로> [--note "한 줄"]` — 이 세션 ID 를 고유번호로 `~/.claude/handoffs/<ID>.json` 에 (저장소·문서·HEAD)를 기록하고 아래 문구를 출력한다. **출력된 문구를 그대로 사용자에게 전달**한다:
   > 새 세션에서 `/donghans-resume <고유번호>` 를 입력해주세요!
   그리고 새 세션에서 달라지는 것(세션 ID, 백그라운드 작업·워크플로우 resume 불가, 다른 세션과의 연결 주소)을 한 줄씩 알린다.
