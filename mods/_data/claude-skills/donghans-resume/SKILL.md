# donghans-resume — 새 세션 복원 (범용, 읽기 전용)

**목표: 사용자가 처음부터 다시 설명하지 않게 한다.** 문서를 믿지 말고 *지금의 상태*를 확인한 뒤 사실·추정·미확인을 구분해 보고한다. 사용자가 「진행」 하기 전에는 코드·문서를 바꾸지 않는다.

## 절차
1. **사실 수집:** `python3 ~/.claude/skills/donghans-resume/scripts/resume.py <고유번호>` (인자가 없으면 생략, 목록은 `--list`).
   - 고유번호 → `~/.claude/handoffs/<ID>.json` → 저장소·문서 경로, 지금의 git 상태(HEAD·미커밋·인수인계 이후 커밋 수·미병합 워크트리), 저장소의 `.claude/resume-extra`(있으면) 출력, 그 세션 트랜스크립트의 사용자 메시지를 한 번에 출력한다.
   - 기록이 없다고 나오면: ID 오타/다른 머신/미등록. 사용자에게 알리고 `--list` 결과나 저장소의 최신 HANDOFF 파일로 대체할지 묻는다.
   - 현재 작업 디렉터리가 기록된 저장소가 아니면 이후 명령은 그 저장소 경로(`-C`/`cd`)에서 실행한다.
2. **인수인계 문서 읽기:** 출력된 `doc` 를 읽는다. 문서에 **상세 문서 인덱스 표**(`<세션ID>/NN-….md`)가 있으면 요약만 보고, 「언제 읽나」에 해당하는 것만 그때 연다(전부 미리 읽지 않는다). frontmatter `focus:` 가 있으면 그 인수인계의 작성 의도로 브리핑에 반영한다. 인수인계 이후 커밋이 많으면(수십 이상) 「현재 상태」는 낡았다고 보고 「상시 지시」「함정」만 신뢰한다.
3. **사용자 지시 복원:** 출력된 사용자 메시지에서 문서에 없는 방침·금지·선호를 찾아 상시 지시에 보태 출처와 함께 보고. 문서의 상시 지시 표에서 확인이 「사용자 원문」이 아닌 항목(문서에서 옮김·에이전트 해석)은 브리핑에서 그렇게 구분해 말한다. 더 필요하면 트랜스크립트(`~/.claude/projects/*/<ID>.jsonl`)를 통째로 읽지 말고 `grep` 으로 좁힌다.
4. **핵심 사실 재확인(필요한 것만):** 문서가 가리키는 브랜치·SHA·파일이 실제로 있는지. 어긋나면 어긋남 자체를 보고.
5. **한국어 브리핑:** ① 한 줄 상태 ② 상시 지시(출처) ③ 미병합·미완 작업 ④ 열린 결정(추천 답, 사용자 결정 대기 vs 진행 중 방침 구분) ⑤ 다음 단계(순서·예상 비용·위험) ⑥ 확인하지 못한 것. 결정이 필요한 것은 한 메시지에 모아 추천 답과 함께.

## 공유 저장소 (donghans ctx)
`resume.py` 는 로컬에 인수인계 기록이 없으면 공유 저장소(Postgres)에서 받아 온다(다른 머신에서 만든 인수인계). 더 파고들 때는 추측하기 전에 `donghans ctx search "<키워드>" --here --role user`, `donghans ctx session <세션ID> --from <uuid8> --to <uuid8>` (인수인계 인덱스의 「근거 대화 범위」) 로 *필요한 구간만* 조회한다. 결과의 `repo_url` 이 현재 저장소와 같은지 확인한다. 접속 실패는 조용히 넘기지 말고 보고한다.

## 프로젝트별 지침 (선택, 보통 `.git/info/exclude` 로 추적 제외)
저장소 루트의 `.claude/donghans-instructions.md`(기본 절차에 **추가 적용**)와 `.claude/donghans-override.md`(기본 절차와 **충돌하면 이쪽이 우선**)가 있으면 따른다. `resume.py` 가 `donghans instr show --section "resume 할 때"` 로 최신화한 뒤 해당 절을 보이므로 따로 읽을 필요 없다(출력에 지침이 없으면 지침이 없는 것). 「생략된 절」 안내(예: 수정 세션용 절)가 나오고 그 내용이 필요하면 `donghans instr show` 로 전체를 본다. 사실 수집 스크립트를 더하고 싶으면 실행 파일 `.claude/resume-extra`.

> **공유 정본(2026-10-23)**: 이 두 파일의 정본은 공유 저장소(ctx DB)이고 로컬 파일은 읽기 전용 캐시다. 읽기는 `donghans instr show`(최신화 후 출력), 고치기는 `donghans instr edit|set`(DB 먼저). `claude` 래퍼의 SessionStart 훅도 세션 시작 때 맞춘다(없으면 만들고, DB 가 더 새로우면 갱신, `.git/info/exclude` 도 보정). 캐시를 우회해 직접 고친 앞섬·충돌은 알림만 하고 덮지 않는다(`donghans instr diff`). 본문에 비밀 값을 적지 말 것(올릴 때 등록표로 검사해 거부).

## 지켜야 할 것
- **사용량 수치는 스냅샷이다.** 5h/7d 한도는 계정 공통인데 기록은 상태 표시줄이 그릴 때만 남는다. 동시에 도는 다른 세션이 올린 만큼은 늦게 반영되므로 `resume.py` 의 「사용량 스냅샷」(기록 시각 포함)을 「약 N% 이상」으로 전하고, 한도 판단은 `claude-limit-watch`(전 세션 기록 기준)나 사용자가 보는 `/usage` 를 우선한다.
- 푸시·DB 초기화·백필 등 되돌리기 어려운 일은 사용자 허가 전에 하지 않는다.
- 하위 에이전트를 띄우기 전에 비용(에이전트당 시작 비용 큼, 모델 선택)을 먼저 말한다. 사용량 지시는 `~/.claude/CLAUDE.md` 「세션 사용량」을 따른다.
- 작업 시작 직전에 `donghans-limit-watch` 스킬로 현재 한도를 확인하고(`status`), 오래 걸리면 `watch` 를 Monitor 로 건다.
