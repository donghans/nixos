# donghans-qa — QA 세션의 범용 원칙 + 프로젝트별 추가 지침

> 이 스킬은 사용자의 워크스테이션 전용이다(프로젝트 저장소에는 없고 `~/nixos` 에서 배포). 프로젝트 고유 내용(계정·포트·스택 기동법·결함 모양·커밋 규칙)은 **그 프로젝트의 `.claude/donghans-instructions.md`(추적 제외 — §0-A)** 에 둔다. 스킬 형식(SKILL.md)·경로(`~/.claude/skills/`)는 Claude Code 기준이고 본문은 에이전트에 중립적으로 썼다.
> 이 원칙은 여러 QA 라운드의 실제 사고 사례에서 **프로젝트와 무관한 것만** 추렸다.

## 0. 시작할 때
### 0-A. 프로젝트 지침 파일 규약 (먼저 이해할 것)
- 프로젝트 고유 QA 지침(계정 정책·포트·스택 기동·결함 모양·커밋 규칙)은 **그 저장소의 `.claude/donghans-instructions.md`**(이 스킬에 **추가 적용**)와 `.claude/donghans-override.md`(**충돌하면 이쪽이 우선**)에 둔다. 실행 파일 `.claude/qa-extra` 는 선택이고, 있으면 그 출력(쓰는 스택·포트·열린 요청 등)이 시작 점검에 붙는다. 파일 안에서는 `## QA 할 때`·`## resume 할 때`·`## handoff 할 때` 처럼 **절 제목으로 용도를 나눈다**(이 스킬은 「QA 할 때」 절을 읽는다).
- 이 파일들은 **git 에 올리지 않는다.** `.git/info/exclude`(저장소 로컬 설정 — `.gitignore` 와 달리 커밋되지 않아 다른 개발자에게 영향이 없다)에 등록한다. **정본은 공유 저장소(ctx DB)이고 로컬 파일은 읽기 전용 캐시다**: 읽을 때는 `donghans instr show`(먼저 최신화한 뒤 출력 — `context.py` 가 이것을 부르므로 다른 머신에서 쓴 내용도 보인다; DB 접속 실패 때만 「낡았을 수 있음」 표시와 함께 캐시를 보인다), 고칠 때는 `donghans instr edit <instructions|override>`(사람) 또는 `donghans instr get` → 고침 → `donghans instr set <이름> --file … --expect-rev N`(에이전트; DB 에 먼저 쓰고 캐시를 맞춘다). 캐시를 직접 고치려 하면 막히고, 우회해도 앞섬·충돌로 잡혀 덮지 않는다(`donghans instr diff`; 예전 방식 `push`·`pull` 은 복구용). 팀원·다른 사람의 클론에는 보이지 않는다. git worktree(예: QA 전용 작업 트리)에서는 메인 체크아웃의 파일을 읽는다(`context.py` 가 처리).
- **경계**: 제품·명세·결함·결정 같은 **프로젝트 사실은 여전히 추적되는 저장소 문서**에 쓴다(전역 원칙). 추적 제외 파일에는 **이 워크스테이션에서 도구를 쓰는 법과 개인 지침**, 그리고 어느 문서가 어디에 있는지 가리키는 색인만 둔다. 팀이 알아야 하는 것은 여기에 숨기지 않는다.
- 처음 보는 프로젝트이거나 파일이 없으면 `context.py --init` — 틀(`## QA 할 때`)을 만들고 추적 제외를 설정한다(멱등, 이미 있는 파일은 덮어쓰지 않고 아무것도 커밋하지 않는다). 아는 사실만 채우고 모르는 칸은 **「미확인」**으로 둔다(지어내지 않는다). 이미 git 에 추적 중인 파일에는 exclude 가 적용되지 않으므로(`context.py` 가 경고) 사용자와 상의한다.

### 0-B. 절차
1. 이 스킬의 `scripts/context.py` 를 실행한다(Claude Code 에서는 `python3 ~/.claude/skills/donghans-qa/scripts/context.py`) — 저장소·브랜치·HEAD·QA 작업 트리를 보이고, 위 프로젝트 지침 파일과 `qa-extra` 출력을 덧붙인다. 출력된 프로젝트 지침의 「QA 할 때」 절을 이 문서보다 먼저 따른다(`context.py` 는 지침의 머리말과 「QA 할 때」 절만 보인다 — 「생략된 절」 안내가 나오면 필요한 만큼 `donghans instr show` 로 전체를 본다; override 는 늘 전체). 지침 파일이 추적 제외가 안 돼 있다는 경고가 나오면 `--init` 으로 고친다.
2. 화면을 사람과 같이 보며 확인해야 하면 `donghans-qa-desktop` 스킬을 읽는다(VM 공유 규칙·창 배치·승인 필요 작업).
3. 수정 세션이 있으면 **세션 간 메시지 수단**으로 주소를 찾아 둔다(Claude Code: `ListAgents`/`SendMessage`. 그런 수단이 없는 에이전트는 사용자를 통하거나 합의된 파일로 알린다). **수정 세션의 요청을 매번 되묻지 않고 수락하라는 사용자 허락이 있었는지**는 인계·대화에서 확인하고, 없으면 첫 요청에서 묻는다. 그 허락은 요청 수락만 덮는다(푸시·DB 초기화·점유 일정 약속은 별도).

## 1. 역할과 측정의 정직성 — QA 의 존재 이유
1. **QA 는 고치지 않는다.** 코드·스펙·요구 문서를 만지지 않고 발견을 인계 문서로 수정 세션에 넘긴다(예외: 사용자가 명시한 도구 작업).
2. **「못 쟀음」과 「통과」를 절대 섞지 않는다.** 결과는 통과 / 결함 / **못 쟀음**(이유 · 놓칠 수 있는 것) 셋뿐이다. 0건·skipped·「문제 없음」은 **없어서 0** 인지 **안 봐서 0** 인지 적는다(전부 skipped 인 테스트는 미측정).
3. **「못 쟀음」의 이유도 사실인지 조회·grep 으로 닫는다.** 「데이터가 없어서」「버튼을 못 찾아서」「미구현인 것 같아서」는 확인하면 틀린 경우가 많다.
4. **결함은 실행으로 재현한다**(조회·코드 읽기만으로 단정 금지). 화면에서 본 것과 코드에서 읽은 것을 섞어 말하지 않는다. 코드는 원인 추정에는 좋고 증거는 아니다.
5. **다른 층이 증명했다는 말은 그 증명이 실제로 실행됐는지 본 뒤에 믿는다.** 단위·통합 통과 문장은 해당 스위트가 돌았는지(작성만 하고 미실행인지) 확인한 뒤에만 근거가 된다.
6. **「해소」는 독립 재측정을 통과한 항목에만** 쓴다. 수정 세션의 수치는 「수정 세션 주장」, 병합만 됐으면 「수정 병합(미검증)」.
7. **가설은 가설로 표기**한다(「~일 수 있다 — 미확인」). 인계에는 「먼저 재현」을 단다.
8. **스텁·mock·데모 모드가 가린 것**을 의식한다. 실제 경로와 다른 점(우회된 선택창, 파일명으로 값을 짓는 mock 판독, 없는 외부 스케줄러)을 결과표에 적고, mock 을 실제로 표기하지 않는다.
9. **문서의 「결함이다 / 미구현이다 / 로그인 불가다」는 그 시점의 관찰이다.** 인용 전에 그 경로의 최근 커밋을 보고 전제부터 다시 잰다. 환경 문제로 보이는 과거 보류 사유를 검증 없이 승계하는 것이 가장 위험하다.
10. **계획(브리프)의 전제를 먼저 검증**한다: 인용한 AC·기능이 현행인지(철회된 버전 서술이 남아 있을 수 있다).

## 2. 범위 설계 — 무엇을 어떻게 나눠 잴까
갭의 출처에서 시작한다: 추적표의 미완 표시·「잔여」 주석, 이전 QA 의 「못 쟀음」 표, 수정 세션의 「작성만 — 미실행」 기록, 사용자가 화면에서 「이상하다」고 한 것(증상 문구를 코드·번역 파일에서 찾아 출처 화면을 특정 → **화면으로 재현**한 뒤 분류).
한 기능을 이 렌즈들로 훑는다(해당하는 것만):
| 렌즈 | 점검 |
|---|---|
| 역할 | 소유 / 타 소유 / 배정 / 미배정 / 상위 / 비인증 — 허용된 쪽이 실제로 되는지(긍정) + 막혀야 할 쪽(404 은닉·403·401) |
| 입력 경계 | 0·음수·소수·지수·천 단위 쉼표·빈값·공백만·상한±1·매우 긴 문자열·이모지·결합 문자·수식 주입(`=`·`@`·`+`·`-` 시작)·날짜 역전·시간대 |
| 파일 | 정상·0바이트·위장 확장자/MIME·스크립트가 든 SVG·상한 근처·초과·**계층별 한도**(프록시→API→앱이 서로 다른 한도·오류 형식을 낸다) |
| 상태 전이 | 허용·역행·건너뛰기·종료 후 쓰기·승인/반려 후 수정·재신청·취소·정정 문서의 재처리 |
| 목록 | **총 건수가 페이지 크기를 넘는 데이터**로 — 끝까지 따라가는지, 「총 N건」이 실제와 같은지, 필터·정렬이 첫 페이지에만 걸리지 않는지 |
| 시간 | 크론·기한·무응답 파생·자정/기한 경계, 외부 스케줄러가 없으면 수동 실행 경로, **멱등**(두 번 실행해도 한 번만) |
| 동시성 | 같은 대상에 N(10+) 병렬 → 1건만 성공·나머지 409, 서로 다른 두 동작이 같은 불변식을 건드리는 교차 경합 |
| 불변성 | 「X 는 돈·판정을 바꾸지 않는다」 → 전후 스냅숏 diff 0 + 양성 대조(일부러 바꾸면 diff 가 잡히는지) |
| 전파 | 한 표면의 쓰기가 다른 역할의 읽기에 주체별 범위로 반영되는가(보여야 할 곳엔 보이고 가려야 할 곳엔 키 자체가 없는가) |
| 표시 | loading·error·empty·success 4상태, 문구(조사·원시 코드 노출·영어 원문 오류), 폭(390·768), 떠 있는 도구·키보드가 가리는지 |
| 계층 | 브라우저 → 프록시 → API → DB — 앞 층에서 막히면 뒤 층의 한도·문구는 사용자에게 안 닿는다 |
| 환경 차이 | 비보안(http) 컨텍스트에서만 막히는 기능(위치·카메라), 데모 모드/실모드, 로컬/서버 구성 차이 |
**세로 시나리오**(예: 주문→결제→처리→정산처럼 업무가 한 바퀴 도는 흐름)는 화면으로 끝까지 한 번 돌며 단계마다 금액·상태를 화면 간 대조한다(항등식이 있으면 단계마다 검사). 단계 일부를 API 로 대체하면 결과표 「방식」 열에 적는다. **폼은 화면에서 채워 제출**하고 API 직접 호출은 서버 응답 대조용으로만 쓴다.

## 3. 병렬 운영·격리 — 시간을 줄이되 서로 오염시키지 않는다
1. **레인을 가르는 기준 = 공유 자원**: UI 디스플레이(VM) · 포트 · 정책 값 · 같은 대상(예: 주문·계정)의 상태 · 레이트리밋 · DB 전체(재시드). 하나라도 공유하면 한 레인으로 묶거나 시간차를 둔다. API 레인은 호스트에서 병렬(공짜), UI 레인은 브라우저 환경 대수만큼.
2. **레인 전용 데이터를 레인이 직접 만들고**(ID 를 보고에 남긴다) 기존 데이터는 읽기만, **삭제는 자기가 만든 행만**. **응답으로 받은 ID 만 쓰고 번호를 추측하거나 행 순서에 의존하지 않는다**(다른 레인의 되돌릴 수 없는 데이터를 건드린 사고 사례). 쓰기 시험 전에 대상의 접두어와 소유를 조회로 확인한다.
3. **정책·전역 값을 바꾸는 시험은 단독 시간대 + 짧게 + 직후 원복 + 전후 diff.**
4. **시험 대상 커밋을 고정한다**: QA 전용 `git worktree add --detach <경로> <커밋>` 에서만 코드를 읽고 `git archive` 로 빌드한다(수정 세션이 움직이는 작업 트리를 읽으면 「아직 있다/이미 고쳐졌다」 판단과 재측정이 어긋난다). **메인 체크아웃의 브랜치를 바꾸거나 원본 브랜치 이름을 독점하지 않는다**(문서 커밋은 `qa/<목적>` 브랜치 + `git fetch` 후 `git push origin HEAD:<대상>` fast-forward only, force push 금지).
5. **데이터 환경을 따로 둔다**: 별도 compose 프로젝트명·포트 대역·전용 볼륨·이미지 태그. 수정 세션의 개발 스택·통합 테스트와 DB·포트를 공유하지 않는다. 결과에는 시험 대상 커밋을 적고, 새 커밋이 올라오면 **새 커밋으로 새 스택을 띄워** 재측정하되 이전 스택은 이전 발견 재현용으로 둔다.
6. **스택을 올린 뒤에는 「시험할 수 있는 상태」를 확인**한다: 건강 검사(200)는 시드 성공을 증명하지 않는다 → 시드 로그 끝줄과 로그인으로 확인. 복사한 스크립트의 포트·경로는 grep 으로 다시 확인(이전 스택의 DB 를 읽어 「0건」이 나온 사례). **검증기·smoke 가 어느 스택을 읽었는지 근거를 보고에 적는다**(로그에 포트가 안 찍히면 「로그의 행 수 = 그 스택 API 목록 수」 같은 확인 가능한 근거). 재활용한 스택의 요약 수치(검증기 위반 건수 등)를 인용할 때는 **어느 레인이 만든 데이터인지** 같이 적는다(경합 재현 잔재가 위반 건수를 두 배 이상으로 부풀린 사례).
7. **메인(오케스트레이터)의 책임**: 브리프 작성 · 중간 확인 · 에이전트가 낸 **high 결함의 샘플 재현**(재현한 것과 관찰만인 것을 인계 표에 구분) · 증거·문서 병합 · 정리 확인. 에이전트의 「통과」는 검증이 아니라 그 에이전트의 관찰이다. 임무는 에이전트당 4개 이하(경험칙: 길어질수록 뒤쪽 임무가 「못 쟀음」으로 밀렸다), 긴 레인을 먼저 시작하고 **레인별 소요를 기록**한다(가장 긴 레인이 총시간을 정한다 — 예: 5레인이 9/26/33/78/77분이면 약 78분, 순차는 약 220분; 다음 라운드의 레인 크기를 정하는 입력).
8. **브리프 체크리스트**: 환경(주소·계정·포트) · 금지(스택 내리기·재시드·삭제·외부 서버 요청) · 필독 문서 · 레인 전용 데이터를 먼저 만들 것 · 「못 쟀음」은 이유·놓칠 것·사실 확인 · 방법(경로)을 모르는 임무에는 경로를 적어 줄 것 · 로그인이 안 되면 측정하지 말고 메인에 알릴 것 · 최종 메시지에 보고 전문.
9. **좌표 클릭으로 되돌릴 수 없는 버튼을 누르지 않는다**(이름·ID 기반 선택, 누르기 전에 화면의 번호를 읽는다). 오조작은 숨기지 말고 보고서 맨 앞에.
10. **한정된 공용 시드 자원(계정·기사·행)은 레인마다 전용으로 먼저 확보**한다 — 레인 간 간섭은 「계정·대상·화면 순서」에서 난다(예: 시드에 담당자가 3명뿐이라 작업이 겹쳐 수락이 막힌 사례).
11. **다른 레인의 되돌릴 수 없는 데이터를 건드린 사고가 나면**: 해당 증거를 무효 처리하고, 회신에 영향 범위(어느 수치가 겹칠 수 있는지)를 적는다. 위험이 큰 쓰기(정정 발행·취소·삭제) 레인은 가능하면 스택을 분리한다.

## 4. 상태 변경 원칙 — 되돌릴 방법부터 확인하고 실행한다
1. **먼저 되돌릴 방법을 찾는다**: 대상이 **append-only 원장**(새로 생긴 행만 특정해 삭제 — 소유자로 필터해 기존 데이터와 혼동하지 말 것)인지 **가변 상태**(실행 전에 원래 값을 조회·기록 → 실행 후 되돌리고, 실행이 만든 파생 필드도 정리)인지 구분한다.
2. 실행 → 3. **재조회로 원래 상태와 일치 확인** → 4. 부수로 생긴 것(알림 문서·감사 기록)을 정리할지 판단(감사 기록은 남겨도 되고, 사용자에게 보이는 알림은 지운다).
5. **되돌릴 수 없는 쓰기(환불·취소 집행·발행·정정·삭제)에 「거절될 입력」을 보낼 때**: 「같은 값으로 미리보기가 거절되면 보내도 된다」는 게이트는 안전하지 않다(미리보기와 집행의 검증이 다를 수 있다). 어떤 값을 보내도 집행이 성립하지 않는 건에만, 입력 처리가 다른 건은 제외, 다른 필드가 유효해지는 조합은 보내지 않는다.
6. **값 목록의 「틀린 입력」에 유효값이 섞여 있지 않은지 칸 종류별로 확인**한다(소수를 허용하는 칸의 `1.5`, 선택 칸의 빈칸·공백은 유효). 쓰기를 일으키는 칸 목록을 먼저 만들고 시험 전 값을 스냅샷해 둔다. 크롤러가 누르는 버튼에서 실행·삭제 계열을 뺀다.
7. **자동 분류기·권한 시스템이 쓰기를 거부하면 우회하지 않는다**(분할 호출·다른 도구로 같은 결과 얻기 금지). 무엇을 하려는지 + 되돌릴 방법을 사용자에게 설명하고 승인을 받거나, 접근 권한이 있는 쪽에 위임하고 결과표에 「미측정(사유)」로 적는다.
8. **운영·공용 서버를 건드릴 때는 식별 가능하게 + 흔적을 보고**한다.

## 5. 보고·증거·인계 규약
- **결과표 열**: 항목 · AC/근거 · **방식**(화면/API/DB) · 판정(통과/결함/못 쟀음) · 근거(증거 파일).
- **발견 ID**: 레인 접두 + 번호(라운드 안에서 유일하게; 새 레인엔 접두 범위를 미리 배정). 심각도는 **사용자 영향** 기준: high = 핵심 동작 불가·돈이 틀림·데이터 노출(돈이 걸리면 high 로 시작), mid = 우회 가능하나 틀림, low = 표시·문구.
- **「관찰」과 「결함」을 분리**한다(명세가 정하지 않은 것·결정 대기는 관찰 + 결정 질문).
- **수정 세션 인계 표는 문서 안에**(구두 설명 금지): ① 바로 fix(기존 AC 안) ② 결정 먼저(**질문형**, 코드로 갈 때·명세로 갈 때의 변경 범위) ③ 환경/구성 ④ 다른 권한이 필요한 확인 ⑤ low 표시. 「외부(고객·타 팀) 결정 대기」와 「개발 담당 방침」을 구분해 전달한다.
- **증거 폴더**: 스크린샷은 보고서가 **인용한 것만**(나머지는 위치만 적는다). **저장소가 `*.log` 를 무시하면 증거 로그는 `.log.txt` 로** 한다(무시 규칙이 인용한 로그를 조용히 빼 푸시된 적 없는 채 두 라운드가 지난 사고) — 어느 쪽이든 커밋 뒤 `git ls-files` 로 **인용한 파일이 실제 추적되는지** 확인. **상태 JSON·`.env`·토큰·시크릿은 넣지 않는다**(커밋 전 느슨한 패턴으로 grep: 로그가 응답을 잘라 적으면 서명 없는 토큰 조각만 남아 엄격한 패턴에 안 걸린다). 새로 만든 계정의 비밀번호가 공용 시드 값이 아니면 문서에 적지 않는다.
- **남긴 데이터**(요청·청구서·계정·정책 변경과 원복 여부)는 반드시 적는다 — 다음 QA 의 입력이자 비교 기준이다. 재시드 전에 사용자에게 알린다.
- 프로젝트 지식은 에이전트의 자동 메모리 기능(Claude Code 의 메모리 등)이 아니라 **저장소 문서**에. 커밋은 명시 경로만(`git add -A` 금지), 문서 커밋은 코드 커밋과 섞지 않는다. 프로젝트별 커밋 규칙(트레일러 등)은 프로젝트 지침을 따른다.

## 6. 환경·도구 함정(일반)
- **zsh**: `$변수:태그` 는 수식어로 해석된다(`$i:latest` → `atest`) → `"${i}:latest"`. 여러 플래그를 변수에 담아 넘기면 깨지니 래퍼 스크립트(bash)로. `for f in $files` 는 줄바꿈으로 안 나뉘니 `while IFS= read -r f`. 에러를 삼키고 `&& echo ok` 하면 실패도 성공처럼 보이니 정리 결과는 다시 센다.
- **`pkill -f <패턴>` 은 자기 셸까지 죽일 수 있다**(명령줄에 같은 문자열) → PID·포트로 지정.
- **compose 는 필요한 포트 변수를 모두 줘야 한다**(빠지면 기본 포트로 재생성하다 충돌). 시드는 멱등이 아니다(재시드는 볼륨째 내렸다 올리고, 모든 레인이 멈춘 뒤).
- **빌드는 커밋된 HEAD 기준**(`git archive`)으로, 작업 트리의 미커밋 변경이 섞이지 않게. 네트워크가 막히는 빌드는 `--network host`.
- **브라우저 자동화**(스택별 예시): 화면 위에 떠 있는 패널·배너가 버튼을 가리면(클릭을 evaluate 로) · React 입력은 네이티브 setter + 이벤트 · Flutter 웹(CanvasKit)은 접근성 플레이스홀더를 눌러야 텍스트가 잡히고 입력은 `pressSequentially` · **스크린샷은 페이지 단위**(`page.screenshot`; 엘리먼트 스크린샷이 캔버스를 비운 사례) · Playwright 위치 에뮬레이션은 좌표를 바꿀 때마다 빈 오류 이벤트를 먼저 낸다 → 이동 시뮬레이션은 페이지에 geolocation 목을 주입.
- **보안 컨텍스트**: 위치·카메라는 `localhost` 또는 https 에서만 — 비보안에서 나오는 오류 문구가 실제 원인과 다를 수 있다.
- **임시 자원은 직접 만든 만큼 지운다**(컨테이너·이미지·env 의 시크릿·임시 DB 행·삽입한 가짜 행·worktree). 남기면 남겼다고 적는다.
- **ssh 로 GUI 프로그램·백그라운드를 띄울 땐** `(cd <디렉터리>; setsid nohup <명령> > log 2>&1 < /dev/null &)`(자세히는 `donghans-qa-desktop`).

## 7. 끝났을 때
**정리 체크리스트**: ① 발견 문서에 결과·발견·못 쟀음·인계 표가 모두 있는가 ② 증거 폴더에 시크릿·상태 파일·대용량이 없고 인용한 스크린샷이 들어갔는가 ③ 임시 컨테이너·env·가짜 행·정책 변경이 정리·원복됐는가(안 했으면 남겼다고 적었는가) ④ 에이전트의 high 결함을 한 번 재현했는가(안 했으면 「미재현(에이전트 보고)」) ⑤ 아래 질문으로 새 규칙을 뽑았는가.
- **하네스·게이트의 반복 결함**(게이트가 거짓말, 집행 없음 등)을 봤다면 **QA 중에 고치지 말고** 프로젝트가 정한 기록 위치에 한 줄 남긴다(위치 이름은 프로젝트마다 다르다 — 프로젝트 지침).
**종료 질문**: ① 「못 쟀음」 중 정말 못 잰 것과 그냥 안 한 것(후자는 다음 라운드 필수) ② 내가(에이전트가) 틀렸다가 바로잡은 주장 ③ 병렬 운영의 오염·충돌·낭비와 레인별 소요 ④ 새로 만난 환경 함정 ⑤ 어느 렌즈가 새 결함을 가장 많이 냈나.
**새로 알게 된 규칙은 어디에 쓰나**: 프로젝트 고유 → 프로젝트의 `.claude/donghans-instructions.md`(「QA 할 때」 절, 추적 제외) 또는 그 프로젝트의 QA 문서. **범용 원칙**이면 이 스킬에 추가해야 하는데, 이 스킬은 `~/nixos` 에서 관리되므로 **QA 세션이 직접 고치지 않고** 사용자에게 「이 규칙을 donghans-qa 에 추가하자」고 제안한다(왜: 어떤 실수가 있었는지 한 줄 포함).
