# donghans-limit-watch — 구독 한도 상태와 감시

5h/7d 한도는 **계정 전체 값**이라 모든 세션의 사용분이 합쳐진다. 기록(`~/.local/share/claude-otel/limits.jsonl`)은 어느 세션이든 상태 표시줄이 갱신될 때만 남는다.

## 1. 지금 상태 (큰 작업 직전에 먼저)
```
python3 -I ~/.claude/skills/donghans-limit-watch/scripts/limitwatch.py status [--recent 30] [--json]
```
한 줄: 5h %·리셋 시각·7d %·최근 N분 증가·마지막 기록 시각, 그 아래 최근 구간 비용 상위 세션. 읽기 전용, 바로 끝난다.
- 70% 이상이면 새 큰 작업을 시작하지 말고 사용자에게 묻는다. 50/80/90% 도 알린다.
- 「마지막 기록 N분 전」이 10분 넘으면 그 사이 사용분은 안 보인다(스냅샷). 사용자에게는 「약 N% 이상」으로 말한다.
- 기록이 없거나 못 읽으면 「못 쟀음」이다. 추측하지 않는다.

## 2. 작업 중 감시 (오래 걸리거나 여러 에이전트를 돌릴 때만)
Monitor 로 실행한다(출력 한 줄 = 알림):
```
python3 -I ~/.claude/skills/donghans-limit-watch/scripts/limitwatch.py watch
```
- 시작 때 **현재 상태 한 줄**을 낸다. 과거 기록은 알림으로 재생하지 않는다(옛 감시기는 시작할 때 과거 전체를 「급증」으로 쏟았다).
- 알림 조건: 10분 내 5h +5포인트(`--spike`·`--window`), 5h 50/70/80/90% 첫 도달(`--levels`). 이미 넘은 수준은 다시 울리지 않고, 5h 창이 바뀌면(`resets_at`) 초기화한다. 주간은 +3포인트마다.
- **소진 예측**(`--forecast 150,200`, 빈 값이면 끔): 창 평균 속도(사용률 ÷ 경과)로 리셋까지 외삽한 도달 예측이 150%·200% 에 연속 두 번(5분 격자) 닿으면 「약 N분 뒤 소진」으로 알린다. 창당 단계별 1회. 경과 30분·사용률 10%p 미만이면 외삽하지 않는다(`--forecast-min-elapsed`·`--forecast-min-used`).
- 알림이 오면 하던 일을 멈추고 사용자에게 알린다. 70% 이상에서는 새 작업을 시작하지 말고 묻는다.
- Monitor 는 지속 시간에 따라 만료된다. 만료되면 다시 걸어도 시작 때 소음이 나지 않는다.
- 감시는 알림 한 건마다 모델 턴을 쓴다. 짧은 작업엔 `status` 한 번이면 충분하다.

## 한계
- 소진 예측은 2일치(5h 창 9개, 소진 2개)로 시뮬레이션했다. 소진 창 2개는 모두 150% 로 3시간 안팎 전에 잡았고, 오탐 창 1개(최고 50%)가 있었다. 창 평균 속도만 쓰면 200% 단계는 이 기록에서 한 번도 울리지 않는다(짧은 몰아쓰기에 둔감한 대신).
- 급증·수준 기준은 경험칙이며 이 계정의 실측으로 보정한 값이 아니다.
- 기록이 상태 표시줄 갱신에 의존하므로 모든 세션이 멈춰 있으면 값이 갱신되지 않는다.
- 창별 최고 사용률 이력은 `donghans ctx limits`.
