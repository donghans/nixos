# 전력·관측 작업 계획 (2026-10-21)

목적: **Wayland 세션을 쓰는 동안의 배터리 최적화**와 "내 사용 습관"에 도움이 되는 인사이트.

**원칙(사용자 확정): 빠르게가 아니라 정확하게 줄인다.** 우선순위 판단은 속도가 아니라 *결론의 정확도*로 한다 — 측정 결과를 더 정확하게 만드는 도구·저장 형식은 측정보다 먼저, 오해를 부르는 이름·정의는 결과 해석보다 먼저 고친다. "측정이 늦어지면 절감이 늦어진다" 같은 속도 논리는 근거로 쓰지 않는다. 측정 근거는 `_docs/content/explanation/power-evidence.md`(장부), 도구 설명은 `observe.md`.

## 0. 현재 상태(요약)
- 수집: `observe-collector`(30초, 스레드 정확, v3) + 시간 제한형 eBPF 정밀 모드(`observectl ebpf`, 장부 #61) + Netdata(별도, 1초).
- 분석 입구: `observectl`(`window`·`ab`·`trace`·`explain`·`bpf`·`ebpf`·`nd`), 화면은 `usageui`(2026-10-21 `powerui` 를 교체).
- 반영됨: PSR1 강제(`psr-force`), 표본 형식 v3, 용어 정정표(L1~L9), `ab` 다지표·자동 검증, `abab_lib.sh` 시험 틀.
- 미푸시 커밋이 많음(푸시는 사용자가 요청할 때 + 공개 정보 스캔 후).

## 1. 구조 결정 (observectl 과 Netdata)
- **observectl 이 분석의 입구**, Netdata 는 켜져 있을 때만 쓰는 데이터 출처(어댑터 `observe_netdata.py`). 꺼져 있으면 해당 항목은 "관측 공백".
- **Netdata 직접 접근이 나은 경우**: ① observectl 이 모으지 않는 신호(앱 그룹 88개 전체 CPU, 네트워크·디스크·온도·포크·인터럽트 종류, 1초 해상도의 짧은 사건) ② 처음 보는 신호를 탐색할 때(REST 질의로 즉석 집계). **observectl 이 나은 경우**: 표지·A/B 판정·스팬·포커스·eBPF·패키지 C-state·PSR·누적 계량, 그리고 모든 결론.
- 규칙: **탐색은 직접 조회해도 되지만, 결론에 쓰는 신호는 어댑터(정의·단위·공백 표시)를 거친다.** → D1 에서 `observectl nd charts|get` 을 만들어 직접 조회도 입구 하나로 모은다.
- Netdata 를 배터리에서 끌지는 **T3 결과 후 결정**(꺼도 observectl 분석은 계속됨).

## 2. 순서 (사용자 필요 여부 표시)
**순서 원칙(정확도 기준)**: 개발(D1: 앱 그룹 저장·Netdata 병기·`ab` 지표·`query`) → 측정(P1·P2) → usageui 리메이크. 개발이 먼저인 이유는 ① 저장 형식은 측정 뒤에 바꾸면 그 측정 데이터에 반영되지 않고 ② `ab` 에 1초 전력 지표를 넣으면 같은 측정이 더 믿을 만해지기 때문이다. usageui 는 저장된 데이터를 읽는 쪽이라 측정 정확도와 무관해 뒤로 둔다.

**병행 규칙**: 측정(P1·P2)은 사용자의 물리 조건(덮개·AC·무입력)이 필요하고, 개발(D1·D3)은 제 작업이라 병행할 수 있다. 단 **측정 중에는 `nixup` 빌드·전체 테스트 같은 CPU 를 많이 쓰는 일을 하지 않는다**(글·설계·코드 작성은 가능). 권장 순서: D1 구현·시험 → P1 → P1 해석 → P2(손대지 않을 수 있는 시간에) → D3 R1~R5(usageui). R0 사양은 측정 중에 글로 써 둘 수 있다.
| 순위 | 항목 | 사용자 | 시간 | 비고 |
|---|---|---|---|---|
| 1 | **P1 측정**: T3 Netdata 켬/끔 5분×3쌍 → T22 낮은 상태 기준선 20분 | **덮개 닫고 AC 뽑고 손대지 않기** | 약 50분 | `examples/netdata_abab.sh`, 끝나면 `explain` 으로 해석 |
| 2 | **P2 측정**: T17 PSR 켬/끔 → T18 PSR 켠 상태 내 활동 비용 → T19 모션·커서 | **덮개 열고 AC 뽑고 손대지 않기** | 약 100분 | 배터리 시간 추정의 근거 |
| 3 | **D1 observectl 자체 개선(2026-10-21 구현 완료: 앱 그룹 v4·`ab` Netdata 지표·`window` 병기·`nd charts/get`·`query`)**: (A) 앱 그룹 단위 저장(전체 프로세스를 앱으로 묶고 나머지 합계 — 상위 16행의 커버리지 한계 해소, 표본 형식 v4)·범용 `observectl query`, (B) 기존 조회에 Netdata 값 병기(`window` 열 추가, **`ab` 에 Netdata 1초 전력 지표 추가** — 순간 V×I 불안정 문제의 근본 해결; 단 Netdata 를 끄는 시험은 그 구간 값 없음)·`nd charts|get` | 불필요 | 반나절 | 설계는 P1 중에 글로, 구현·시험은 P1 뒤 |
| 4 | D3 **usageui 제로베이스 리메이크(아래 §3)** | 설계 검토만 | 반나절~1일 | P1/P2 와 병행 가능(측정 중에는 무거운 빌드·테스트만 피함), R0 사양은 P1 중에 글로 |

## 3. usageui 제로베이스 리메이크 사양 (2026-10-21 구현·교체 완료 — 최종 구성은 observe.md `usageui` 절. 아래는 최초 제안)
**원칙**: ① 조회는 **시간 범위 기준**(기본 = 현재 시각까지의 최근 1시간) ② **갱신은 수동만**(타이머 없음 → PSR 을 방해하지 않고 측정 중 열어 둬도 영향 없음) ③ 이름은 단위·출처·"측정/추정"이 드러나게 ④ 프로세스 **관리**(종료·nice)는 btop, 프로세스 **지표(누가 전력을 쓰나)** 는 여기 ⑤ uikit 규약 재사용.

- **앱 이름**: **`usageui`**(전력+자원 사용 습관) — 사용자 확정, `powerui` 별칭은 두지 않는다(리메이크 때 교체하고 옛 이름은 제거). 이름 충돌 확인 완료(`usageui`·`energyui`·`resourceui`·`hwinfoui` 모두 없음).
- **조회 모델**: 범위 [시작, 끝] — 프리셋 키(1시간·6시간·오늘·어제·3일), 직접 입력(`10:00`, `-30m`, `2026-10-21 09:00` — `parse_when` 재사용), 기준 구간 선택(바로 앞 / 어제 같은 시간대 / 직접). 상단에 "데이터 기준 HH:MM:SS(지금까지) — F5 로 갱신", 오래되면 표시. 큰 범위는 스레드에서 불러오며 진행 표시.
- **탭(안)**: ① **요약** — 구간 카드: 평균 전력·배터리 사용량(Wh·%)·예상 사용 시간(신뢰 표시)·가장 많이 쓴 앱·화면 켜진 시간·PSR 시간·low 시간·충전 횟수·`nixup` 에너지 ② **전력** — 4지표 그래프 + 상태 띠 + 표지·스팬 마커 ③ **앱·프로세스** — 포커스 앱 시간, 앱별 에너지 **추정**(CPU 시간 점유 × 전력, 추정 표시), 프로세스 CPU·전환 표, eBPF 정밀 표(있을 때) ④ **원인** — 기준 구간 비교(현재 explain) ⑤ **시스템 지표** — Netdata(있을 때; 없으면 "관측 공백"과 이유) ⑥ **하드웨어·배터리** — 배터리 건강(현재 만충/설계), 온도, 주파수, PSR·부팅 인자·서비스 상태, 수집 상태 ⑦ **도움말·용어** — 정정표 요약.
- **상호작용**: 그래프에서 시점 선택 → 그 앞뒤로 **원인** 탭 이동, 스팬·표지 목록에서 선택, `b` 로 btop 열기, `e` 로 현재 보기를 텍스트 파일로 내보내기, `ebpf` 정밀 모드 켜기(단계·제한 시간 확인 창).
- **구조**: 데이터 계층(`RangeQuery` → 보기 모델: observe 표본·이벤트·스팬·eBPF + Netdata 어댑터, 캐시·증분 읽기) / 위젯 계층(점자 차트·띠·표·카드) / `uikit`. 순수 계산은 터미널 없이 시험, 화면은 Textual 시험 + 실제 화면 스크린샷 확인.
- **단계**: R0 사양·와이어프레임 확인 → R1 데이터 계층(수동 갱신·범위 모델) → R2 탭(요약·전력·앱·프로세스) → R3 원인·시스템·하드웨어 → R4 상호작용·이름·도움말 → R5 문서·테스트·스크린샷·`nix` 교체(옛 powerui 는 제거). 각 단계는 테스트 통과 + 실제 화면 확인 후 커밋.
- **비목표**: 프로세스 종료·우선순위 조정, 1~2초 실시간 갱신(btop 의 몫).

## 4. 결정이 필요한 것
1. (확정) 앱 이름 `usageui`, 별칭 없음.
2. Netdata 정책(배터리에서 끌지) — P1 결과 후.
3. 푸시 시점.
