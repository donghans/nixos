# 전력 최적화 — 상태 기반 디버깅 로드맵 v3 (2026-10-26, v2 는 2026-10-24, v1 은 2026-10-23)

대상 호스트: msi-summit-me(MSI Summit E16 Flip, Intel hybrid, i915, Hyprland 0.55, 커널 6.18). 기존 계획 `power-observability-roadmap.md`(T 번호 시험 목록)을 대체하지 않고 **방법론을 한 단계 올린** 문서다. 실측 장부는 `_docs/content/explanation/power-evidence.md`(#1~#135, 이 문서가 인용하는 #85~#90 은 2026-10-23~24 에 노트북을 데스크톱에서 원격 조작해 잰 것).

## 0. 원칙
1. **와트는 최종 확인용, 상태는 디버깅용.** 전력은 깨움 횟수·패키지 C-state 잔류·GPU RC6·PSR 잔류·장치 상태의 결과다. 상태 카운터는 정수이고 원인(누가 깨웠나)까지 따라갈 수 있어 와트 비교보다 소음이 작다. 단 상태는 와트로 환산하려면 보정이 필요하고, 깨움은 **단순 합이 안 된다**(깊은 절전은 비는 시간이 일정 길이 이상일 때만 들어감 — 유휴 거버너, 장치 LTR, 타이머 슬랙). 그래서 와트 ABAB 는 버리지 않고 상위 후보만 확인한다.
2. **분해 단위는 「깨움 사건 하나와 그 원인 사슬」**(타이머 만료/IRQ → 태스크 → 작업 → 유휴 복귀)이고, 핵심 상태 변수는 **깨움 사이 간격의 분포**다. 프로세스나 서비스 단위로 끄는 것은 이 단위의 합이 아니다.
3. **개입 실험(ABAB)은 인과를 준다.** 약점은 인과가 아니라 측정의 거칠기와 교란이다 → 측정 격자·소음 폭·환경 고정을 먼저 고친다.
4. **교란은 의심하고 같은 조건에서 재측정한다.** 이동 중 측정이 재측정에서 사라진 사례가 이미 있다(§1).
