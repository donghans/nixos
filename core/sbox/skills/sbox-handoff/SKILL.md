# 결과를 사용자에게 넘기기

이 컨테이너에는 **푸시 자격증명이 없고** 컨테이너는 지워질 수 있다. 반영은 사용자가 번들·diff 를 가져가서 한다. 그래서 **넘기는 내용이 곧 작업의 결과물**이다.

## 넘길 것(한 번에, 이 순서)
1. **한 줄 상태**: 끝났다 / 일부만 됐다 / 막혔다 — 과장 없이.
2. **무엇이 바뀌었나**: `git status`·`git diff --stat` 로 확인한 파일 목록과 각 변경의 이유 한 줄. **제어 파일**(`CLAUDE.md`·`.claude/**`·`.mcp.json`·`package.json`·락 파일·`Dockerfile*`·`docker-compose*.yml`·`.githooks/**`·`.github/**`)을 건드렸다면 **따로 모아 이유를 적는다** — 사용자가 가장 먼저 봐야 하는 부분이다.
3. **확인한 것과 확인 못 한 것**: 실행해서 본 결과(명령과 결과 한두 줄)와, 못 돌렸거나 안 돌린 것(이유 포함)을 **구분**한다. 「통과」는 실제로 돌려서 본 것에만 쓴다. 돌리지 않은 시험을 통과로 적지 않는다.
4. **사용자가 해야 할 일**: 승인이 필요한 확인 프롬프트가 남았는지, 허용 호스트·비밀처럼 사용자만 줄 수 있는 것이 필요한지, 반영(커밋·푸시) 전에 볼 것.
5. **이어서 할 일**: 다음 세션이 처음부터 다시 묻지 않게 — 결정이 필요한 것과 추천 답, 하던 방향, 알게 된 함정.

## 하지 않는 것
- 변경을 숨기거나 줄여 말하지 않는다. 실패한 시도·되돌린 변경도 한 줄로 남긴다.
- 푸시를 시도하거나 자격증명을 찾지 않는다. 이 환경에서 반영은 사용자 몫이다.
- 비밀·토큰 값, 자리표시자 토큰을 보고에 옮겨 적지 않는다.
- 파일에 남기는 인수인계 문서를 만들기 위해 `CLAUDE.md`·스킬 같은 구성 파일을 쓰지 않는다(확인 프롬프트 대상이고 다음 세션의 지시가 바뀌는 경로다). 필요하면 대화로 넘기거나 사용자가 정한 위치에 일반 문서로 둔다.
