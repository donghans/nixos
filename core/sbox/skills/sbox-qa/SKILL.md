# sbox 에서 QA 하기

## 1. 역할과 측정의 정직성
1. **QA 는 고치지 않는다.** 코드·명세를 만지지 않고 발견을 보고서로 넘긴다(사용자가 명시한 도구 작업은 예외).
2. **「못 쟀음」과 「통과」를 절대 섞지 않는다.** 결과는 **통과 / 결함 / 못 쟀음**(이유 · 놓칠 수 있는 것) 셋뿐이다. 0건·skipped·「문제 없음」은 **없어서 0 인지 안 봐서 0 인지** 적는다. 전부 skipped 인 시험은 측정하지 않은 것이다.
3. **「못 쟀음」의 이유도 사실인지 조회·검색으로 닫는다.** 「데이터가 없어서」「버튼을 못 찾아서」「미구현인 것 같아서」는 확인하면 틀린 경우가 많다. **부재·미동작 주장은 한두 방식으로 못 찾은 것만으로 확정하지 않는다** — 서로 다른 방법 3가지 이상으로 닿아 보고, 직접 지표(주소·화면 노드 집합의 전/후 차이·네트워크 응답)로 판정한다.
4. **결함은 실행으로 재현한다.** 코드를 읽은 것은 원인 추정에는 좋지만 증거는 아니다. 본 것과 읽은 것을 섞어 말하지 않는다.
5. **다른 층이 증명했다는 말은 그 증명이 실제로 실행됐는지 본 뒤에 믿는다**(작성만 하고 안 돌린 시험이 흔하다).
6. **「해소」는 독립 재측정을 통과한 항목에만** 쓴다. 수정한 쪽의 수치는 「수정한 쪽 주장」이다.
7. **가설은 가설로 표기**한다(「~일 수 있다 — 미확인」).
8. **스텁·mock·데모 모드가 가린 것**을 의식하고 실제 경로와 다른 점을 결과표에 적는다. mock 을 실제로 표기하지 않는다.
9. 문서의 「결함이다 / 미구현이다」는 그 시점의 관찰이다. 인용하기 전에 현재 코드·동작으로 다시 확인한다.

## 2. 범위 설계 — 무엇을 어떻게 나눠 잴까
한 기능을 이 렌즈로 훑는다(해당하는 것만):
| 렌즈 | 점검 |
|---|---|
| 역할·권한 | 허용된 쪽이 실제로 되는지(긍정) + 막혀야 할 쪽(401·403·404 은닉) |
| 입력 경계 | 0·음수·소수·빈값·공백만·상한±1·매우 긴 문자열·이모지·수식 주입(`=`·`@`·`+`·`-` 시작)·날짜 역전·시간대 |
| 파일 | 정상·0바이트·위장 확장자·상한 근처·초과, **계층별 한도**(프록시→API→앱이 서로 다른 한도·오류 형식) |
| 상태 전이 | 허용·역행·건너뛰기·종료 후 쓰기·재신청·취소 |
| 목록 | **총 건수가 페이지 크기를 넘는 데이터**로 — 끝까지 따라가는지, 「총 N건」이 실제와 같은지 |
| 시간 | 기한·자정 경계·**멱등**(두 번 실행해도 한 번만) — 시간 이동은 아래 `faketime` |
| 동시성 | 같은 대상에 N 병렬 → 1건만 성공·나머지 409 |
| 불변성 | 「X 는 값을 바꾸지 않는다」 → 전후 스냅숏 diff 0 + 양성 대조(일부러 바꾸면 diff 가 잡히는지) |
| 표시 | loading·error·empty·success 4상태, 문구, 폭(예: 390·768) |
세로 시나리오(업무가 한 바퀴 도는 흐름)는 끝까지 한 번 돌며 단계마다 값을 대조한다. 단계 일부를 API 로 대체하면 결과표 「방식」 열에 적는다. 폼은 화면에서 채워 제출하고 API 직접 호출은 서버 응답 대조용으로 쓴다.

## 3. 격리 — 시간을 줄이되 서로 오염시키지 않는다
- **공유 자원(포트·계정·DB·정책 값·레이트리밋)을 하나라도 공유하면 한 레인으로 묶거나 시간차를 둔다.**
- **레인 전용 데이터는 레인이 직접 만들고**(ID 를 보고에 남긴다) 기존 데이터는 읽기만, **삭제는 자기가 만든 것만**. **응답으로 받은 ID 만 쓰고 번호를 추측하지 않는다.**
- **정책·전역 값을 바꾸는 시험은 단독 시간대 + 짧게 + 직후 원복 + 전후 diff.**
- **시험 대상 커밋을 고정**한다(`git worktree add --detach <경로> <커밋>` 에서 읽고 빌드). 작업 트리가 움직이면 재측정이 어긋난다.
- 스택을 올린 뒤에는 **「시험할 수 있는 상태」를 확인**한다(건강 검사 200 은 시드 성공을 증명하지 않는다 — 로그인과 시드 로그 끝줄). 어느 스택·포트를 읽었는지 근거를 보고에 적는다.
- 좌표 클릭으로 되돌릴 수 없는 버튼을 누르지 않는다(이름·ID 로 선택, 누르기 전에 화면에서 읽기).

## 4. 상태 변경 — 되돌릴 방법부터 확인하고 실행한다
1. 대상이 **append-only**(새로 생긴 행만 특정해 삭제)인지 **가변 상태**(실행 전에 원래 값을 기록 → 실행 후 되돌림)인지 구분한다.
2. 실행 → **재조회로 원래 상태와 일치 확인** → 부수로 생긴 것 정리 여부 판단.
3. **되돌릴 수 없는 쓰기(환불·취소·발행·삭제)에 「거절될 입력」을 보내는 것은 안전하지 않다**(미리보기와 집행의 검증이 다를 수 있다).
4. **자동 분류기·권한 시스템·확인 프롬프트가 쓰기를 거부하면 우회하지 않는다.** 무엇을 하려는지와 되돌릴 방법을 사용자에게 설명하거나 「못 쟀음(사유)」로 적는다.
5. **요청 한도(429)에 걸리면** 한도 때문에 막힌 결과를 결함으로 세지 말고 원인(어느 계층의 한도인지)을 확인해 「못 쟀음(한도로 막힘)」으로 적는다. 한도를 올려야 하면 **내가 띄운 로컬 스택에서만**, 올리기 전 원래 값을 기록하고 끝나면 되돌려 재조회로 확인한다. 추적되는 소스를 고치지 않는다.

## 5. 보고
- **결과표 열**: 항목 · 근거 · **방식**(화면/API/DB) · 판정(통과/결함/못 쟀음) · 증거 경로.
- **심각도는 사용자 영향 기준**: high = 핵심 동작 불가·값이 틀림·데이터 노출, mid = 우회 가능하나 틀림, low = 표시·문구.
- **「관찰」과 「결함」을 분리**한다(명세가 정하지 않은 것은 관찰 + 결정 질문).
- **수정하는 쪽에 넘기는 표는 문서 안에**: ① 바로 고칠 것 ② 결정이 먼저인 것(질문형) ③ 환경·구성 ④ 사용자 권한이 필요한 확인 ⑤ low.
- **증거는 `~/work/qa-evidence/<라운드>/` 에 두고** 보고서가 인용한 것만 남긴다. 컨테이너는 지워질 수 있으니 사용자가 가져갈 수 있게 경로를 적는다. 남긴 데이터(만든 계정·행·바꾼 값과 원복 여부)를 반드시 적는다.
- 임시 자원(컨테이너·이미지·임시 파일·가짜 행)은 만든 만큼 지우고, 남겼으면 남겼다고 적는다.

## 6. 이 환경(ct)에서 되는 것과 안 되는 것 (직접 확인한 것 위주)
- **시간 이동**: 시스템 시계는 ct 에서 바꿀 수 없다(root 도 불가). 프로세스 단위로는 `faketime`(libfaketime)이 된다 — 고정 시각·상대 오프셋, Docker 컨테이너에도(glibc·musl 모두, 이미지는 수정하지 않고 라이브러리 파일만 읽기 전용 마운트하고 `LD_PRELOAD`·`FAKETIME` 환경변수). **여러 프로세스·컨테이너가 같은 시각을 봐야 하면 공통 상대 오프셋(`+30d`)을 쓴다** — 절대 시작(`@…`)은 프로세스마다 시작 시각으로 리셋돼 순차 기동하는 스택에서 어긋난다. 정적 링크 바이너리·DB 서버·외부 서비스(인증서·토큰 검증은 진짜 시각)에서는 보장되지 않는다.
- **headless 브라우저**: 영상(`recordVideo`)·스크린샷·트레이스가 headless 로 모두 만들어진다. 창 크기(`viewport`)·확대(`deviceScaleFactor`·CSS zoom)도 조절된다. 페이지 포커스는 에뮬레이션돼 여러 탭이 모두 포커스·표시 상태로 보이며, **OS 창 포커스·입력기(IME)·창 배치 같은 실제 데스크톱 동작은 확인할 수 없다**(그것은 별도 환경의 몫).
- **브라우저 내려받기·외부 사이트**는 허용 목록 밖이면 거부된다. 그러면 「못 쟀음(허용 호스트 없음)」으로 보고하고 필요한 호스트와 이유를 사용자에게 알린다.
- 호스트 도구·호스트 문서 저장소는 없다. 호스트 쪽 증거 보관이 필요하면 보고서에 경로를 적어 사용자가 가져가게 한다.
